# Nexus — 產品規格（使用者畫面與操作契約）

> 以功能模組為單位，描述使用者從何處進入、看見哪些 UI、如何操作、可以修改哪些設定，以及操作後的結果。未確認的尺寸、手勢、預設值與流程標示「待核准」。產品歷史記於 [HISTORY](HISTORY.md)，程式修改與驗收狀態記於 [HANDOFF](HANDOFF.md)，技術及資料庫設計記於 [ARCHITECTURE](ARCHITECTURE.md)。

## 文件閱讀方式
- 各 `F-*` 章節是產品需求主要來源；同一功能的入口、畫面、操作、設定與資料集中紀錄。
- 精確 UI 位置、順序、大小、間距、導覽、狀態和跨裝置差異，一旦確認即寫入所屬模組，不另建立重複總表。
- 使用者未設定而ai自行設定的規格也要紀錄於此，方便後續的調整

## 功能規格

### F-HOME — 首頁
- 側邊欄「新增+」按鈕，應對應新建功能跳出相應的格式選擇，例如:筆記-分頁、流動，創作-世界觀、角色
- 排序下拉新增「依照項目類型」勾選框

### F-NOTE — 筆記

#### 功能定位與入口
- Nexus 筆記是一種可自由編輯的富文字內容，使用者可以透過同一套編輯工具製作一般筆記、整理資料、題庫、測驗題、考卷或類似講義的內容。
- 使用者從首頁、筆記清單或新增功能進入筆記；開啟筆記後直接進入同一筆記編輯器，並可使用側欄、搜尋及既有工作區導覽返回。
- 筆記的內容及排版會持續儲存；重新開啟、重新整理、備份與同步後仍保留。
- 側邊欄項目隨時可拖拽（拉出/拉入子頁）

#### 筆記畫面與編輯工具
- 筆記編輯區提供標題、正文、富文字工具列與「插入內容／格式」等工具入口；既有工具以相同互動方式供所有筆記使用。
- 可使用段落、標題層級、粗體／斜體等文字樣式、項目符號、編號清單、引用、連結、待辦清單、表格、提示框、程式碼、行內與區塊數學式。
- 可使用二欄／三欄、多種文字方向、圖片與圖說、手動分頁，以及拖曳把手調整區塊次序。不同工具在其適用的內容位置提供插入、編輯、移動和移除操作。
- 插入工具及格式設定在桌面／平板／手機保留可觸達入口；窄螢幕可透過「更多」選單提供完整工具清單，浮動選單維持在可視範圍內。
- 右鍵或相應的觸控選單可對文字、區塊與表格執行適用操作；文字選取和系統鍵盤不應遮擋主要編輯目標。

#### 題目、題號與選項（通用筆記編輯能力）
- 使用者可以在筆記的任意位置插入題目內容，不限於特定筆記類型或版面。題目可搭配文字、數學式、圖片、表格及其他筆記區塊。
- **題號**：可插入自動編號題目，按內容順序編號；新增、刪除、拖曳或調整題目順序後，題號隨之更新。題號起始值、編號樣式、分段重新編號與巢狀規則待確認。
- **選項**：可在題目內插入多個選項，包含選項標籤與可編輯內容；支援常見單選題 A／B／C／D 類排列，也可按需求增減選項。選項標號樣式、橫向／縱向／多欄排列、長內容換行與編輯方式待確認。
- **答案與解析**：可在題目後插入答案或解析區塊，內容可編輯；提供展開／收合能力，方便在編輯或檢視時按需要顯示。
- **作答空間**：可在任意段落或題目後插入留白區域，供閱讀、列印或手寫作答使用；留白高度／行數可調，預設值待確認。
- 定義、例題、練習、解答及重點等語意區塊可作為一般筆記的插入內容；可設定區塊標題、內容及可用的展示方式。
- 題目、選項、答案和其他編輯區塊能與普通段落交錯排列，並保有完整的剪下、複製、移動、儲存、匯出及復原能力。

#### 內容組織與導覽
- 使用者可依標題層級產生自動目錄，點擊目錄項目跳轉到所屬標題；增刪或修改標題後更新目錄文字與定位。
- 支援標籤、資料夾、頁面連結、反向連結、附件及內容區塊編排；筆記可與工作區其他資料建立關聯。
- 圖片可設定圖說，題目及圖表可具有可辨識的編號或參照資訊；跨區塊引用的操作與自動更新細則待確認。

#### 版面、列印與匯出
- 筆記支援流動（Flow）、A4 分頁等版面設定，並可調整正文字級、行距、標題樣式、內距、頁首頁尾及頁碼等適用選項。
- 分頁筆記可使用手動分頁；使用者可主動執行「依 A4 整理分頁」，檢查區塊高度與排版，在合理範圍內維持標題與內容、圖片與圖說及題目與選項的相鄰關係。整理後可復原。
- 列印及 PDF 匯出呈現筆記內文、題號、選項、答案、圖說、頁碼與頁首頁尾；收合內容在列印時仍應完整輸出。
- 筆記可列印、匯出 PDF，以及透過 Nexus JSON 或工作區備份保留完整可編輯內容與格式。Markdown 可作內容交換用途，其支援格式依筆記與 Document 各自的匯出契約處理。

#### 設定與待確認事項
- 筆記相關設定依適用範圍保存：全站偏好、單篇筆記版面設定，以及個別題目／區塊屬性分開處理。
- 題號樣式、選項預設數量與排列、答案顯示狀態、作答空間預設高度、工具列位置及尺寸、手機觸控插入流程均待使用者確認；在定案前保留現有一般筆記的操作方式。

### F-DOCUMENT — Plain Document

- **文檔（F-DOCUMENT）**：純文字與 Markdown 導向的文件編修和匯入匯出。

- **目的**：適合文章、報告、正式文字與 Markdown 工作流。
- **編輯模式**：`plain` editor variant；不承擔 Note 的 rich typography 工具列。
- **格式**：以 flow／A4／custom 為主；Document 預設 A4 的目前規則見 F-PAGEFORMAT。
- **匯出**：Markdown；需在 export 前 flush save。
- **定位**：Document 為純文字／Markdown 導向的獨立編輯流程，Note 為富文字筆記編輯流程。

#### 文件匯入與匯出

- 使用者可將 `.md`、`.markdown`、`.txt` 匯入為 Document；匯出 Markdown 前保存當前編輯內容。

### F-PDF — PDF 文件與研究筆記

- **PDF 研究（F-PDF）**：PDF 匯入、檢視、附檔及關聯研究筆記；進階 PDF 工作空間待細化。

#### PDF 匯入與 Research Note

```
選擇本地 PDF
→ 建立 Attachment metadata
→ 寫入 binary
→ 自動建立 Research Note Page
→ attachment_ids / primary_attachment_id 關聯
→ 顯示 PDF viewer 與研究筆記
```

- PDF binary 不放入 `content_json`；以 attachment／asset 管理。
- 一篇 PDF 對一篇主 research note 是起步 UX，不是資料模型硬限制。
- Viewer 現有 Open、Small/Medium/Large、Hide/Show、loading/unavailable/normal 三態。

#### PDF 文件工作空間（待定案）

- **使用者要求**：PDF 應以「匯入」形式進入 Nexus，形成類似 GoodNotes 的 PDF 文件工作空間，而不是把 PDF 視為一般 rich-text insert。

- **相容性**：PDF 文件工作空間與 Attachment／Research Note 的既有資料及操作流程相容。

#### PDF 匯入與文件整理

- 使用者選取 PDF，系統建立附件並開啟關聯的 Research Note 與 PDF viewer；進階 PDF 文件工作空間的手寫、註解及頁面操作待核准。

F-STUDY — 學習集與字卡

本次改版追蹤：#47；以下產品契約取代舊 #47／#48 的 50 張上限與非正式額外練習規則。

1. 開始學習

- 統一入口：點擊「開始學習」建立 Study Session，使用者先回想字卡對應的答案，再點擊「查看答案」，根據記憶狀況選擇「熟記／知道／困難／忘記」。
- 正式學習：所有正式作答皆記錄作答時間、選項、字卡狀態及排程結果，並依目前選用的排程方法計算下一次到期時間（due）。
- 學習設定：開始 Session 時讀取該學習集目前套用的字卡樣式。進行中的 Session 保留建立時的設定，不因使用者修改樣式而突然改變學習規則。

2. 單次名額與每日新卡

- 單次複習上限：每次開始學習，預設最多選入 100 張不同字卡，包含新卡與複習卡，可由使用者調整。此上限僅適用於當次 Session，不是每日複習總上限；本批完成後，使用者可再次從「開始學習」入口建立下一批。
- 每日新卡上限：每個學習集預設每天最多引入 20 張新卡，可由使用者調整。每日新卡額度為同一學習集當日所有 Session 共用，不因重新開始學習而重置。
- 每日換日：依使用者裝置當地日期，於 00:00 切換學習日並刷新每日新卡額度。不需要在午夜自動建立 Session；下次開始學習時依當日額度選取新卡。
- 新卡計數：新卡首次正式呈現時，使用 "introduce" 事件扣除當日新卡額度。僅預先選入 Session、載入或預覽字卡，不視為正式引入。
- 暫停新卡門檻：當學習集中目前已到期、尚待複習的舊卡數量達到設定門檻（預設 200 張）時，停止引入新卡，但仍依目前學習模式安排舊卡。當已到期舊卡數量低於門檻時，恢復引入新卡，仍須遵守當日剩餘新卡額度。
- 門檻計算：已到期舊卡包含符合到期條件的 Review、Learning、Relearning 不同字卡，不包含尚未到期的舊卡及未引入的新卡。同一張卡只計算一次。
- 名額計算：同一張字卡在同一 Session 中只占用一個不同字卡名額。因短間隔 Learning／Relearning 而再次出現，不重複占用名額。

3. 排程模式與無盡模式

兩種模式均為正式學習，使用相同的字卡記錄、排程方法、每日新卡額度及單次複習上限。兩者唯一的抽卡差異，是是否允許提前選取尚未到期的舊卡。

- 正常排程模式：依目前排程選取已到期舊卡及當日符合條件的新卡，不提前抽取尚未到期的舊卡。正常候選不足單次上限時，以實際可選數量建立 Session。
- 無盡模式：先依正常排程規則選取已到期舊卡及符合條件的新卡。僅當正常候選不足單次上限時，才依到期時間由近至遠，提前選取尚未到期的已學卡補足名額。
- 強制解凍限制：無盡模式只從尚未排入當次 Session 的合格舊卡補位，不重複抽取同一張卡。如果整個學習集符合條件的不同字卡少於單次上限，則以實際可選數量建立 Session，不強制重複抽卡。
- 正式評分：無盡模式提前複習的字卡仍屬正式複習；作答後必須記錄結果，依目前排程方法和實際作答時間重新計算 due，不保留舊 due 假裝沒有作答。
- 暫停新卡門檻：兩種模式都遵守暫停新卡門檻。達到門檻後仍優先安排已到期舊卡；只有無盡模式在正常候選不足時可以提前抽取未到期舊卡。
- 不設額外練習流程：無盡模式直接從「開始學習」入口啟動，不需要先完成正常排程，也不是不更新正式排程的獨立練習功能。

4. 固定排程

固定排程由使用者設定四種回答選項的間隔，作答後按照所選間隔計算下一次到期時間，不由 FSRS 動態決定。

一般複習（Review）的預設間隔：

回答選項| 預設間隔
熟記| 7 天
知道| 3 天
困難| 1 小時
忘記| 5 分鐘

新卡（New）與重新學習（Relearning）的預設間隔：

回答選項| 預設間隔
熟記| 4 天
知道| 1 天
困難| 10 分鐘
忘記| 1 分鐘

固定排程狀態轉換：

- New／Relearning → Review：選擇「熟記」或「知道」後，進入一般複習狀態，並依本次回答的對應間隔安排 due。下次作答使用一般複習的時間設定。
- New／Relearning 維持學習：選擇「困難」或「忘記」時，維持當前學習／重新學習狀態，依對應短間隔安排下一次出現。
- Review 維持複習：選擇「熟記」「知道」或「困難」時，維持 Review 狀態，依一般複習間隔更新 due。
- Review → Relearning：選擇「忘記」時，進入重新學習狀態，本次依一般複習的「忘記」間隔（預設 5 分鐘）安排下一次出現；下一次作答開始使用 New／Relearning 的四種回答間隔。

時間設定與紀錄：

- 固定排程中的各回答間隔可以透過字卡樣式修改，不限制為預設值。
- 按鈕顯示依目前卡片狀態及樣式設定計算的實際預計間隔。
- 每次正式作答都保存當時採用的排程方法、回答選項、實際作答時間和計算結果，供後續同步、歷史查詢及排程切換使用。

5. FSRS 排程

- 演算法：沿用 Nexus 現有的 FSRS-6，依每張字卡的歷史作答紀錄、記憶穩定度、難度及實際複習時間，動態計算下一次到期時間。
- 回答對應：「熟記／知道／困難／忘記」分別對應 FSRS 的 Easy／Good／Hard／Again。
- 預計間隔：回答按鈕顯示依 FSRS 即時計算的預計間隔，而非固定排程設定值。
- 新卡與重新學習：保留符合 FSRS 的 Learning／Relearning 狀態與短間隔機制；短間隔到期時依實際時間安排再次作答。
- 無盡模式相容：提前抽取尚未到期的舊卡時，使用其當前 FSRS 狀態及實際作答時間正式評分，更新記錄與 due。
- 排程完整性：不得為了填滿單次名額而直接修改未作答字卡的 due，或偽造複習事件。

6. 排程方法切換與歷史保護

- 可切換方法：字卡樣式可選擇固定排程或 FSRS，兩種方法與正常排程／無盡模式獨立，可以自由組合。
- 保留歷史：切換排程方法不得刪除既有作答事件、字卡記錄、引入日期、學習進度或版本資訊，也不得將已學卡直接重置為 New。
- 狀態隔離：固定排程與 FSRS 使用各自適用的排程狀態，不得把固定間隔直接當成 FSRS 記憶穩定度或難度參數。
- 安全轉換：切換排程方法時，需依現有作答歷史與可用資料採用明確、可重現的狀態轉換策略。無法可靠轉換的資料不得自行推測或偽造歷史，應採取安全且可追溯的相容處理。固定排程期間保留原 FSRS 記憶狀態；回切後以該狀態及真實作答時間計算，不把固定作答偽裝為 FSRS 歷史。沒有可靠 FSRS 記憶的已學卡保留目前進度與 due，於下一次真實 FSRS 作答建立記憶狀態，並記錄此相容轉換。
- 生效時機：新排程方法適用於之後建立的 Session；尚未完成的 Session 繼續使用建立時的設定。
- 資料同步：排程方法、狀態及切換結果必須與既有離線、跨裝置同步和衝突處理機制相容。

- **Session 完成、等待與恢復**

- 學習進度：學習中顯示本次已完成的不同字卡數、總名額及必要的學習進度。
- 短間隔等待：已選入 Session 的 Learning／Relearning 字卡，如下一次作答時間尚未到期，應顯示等待狀態，而非直接宣告本次完成。
- 短間隔續作：已開始的短間隔卡片到期後，仍需完成必要作答；同一卡再次出現不重複占用單次名額。
- 完成條件：當本次所有必要的正式學習步驟完成後，Session 才可標記完成。
- 完成畫面：僅顯示「恭喜你完成這次學習」，不在完成畫面提供開始下一批或切換模式的續接按鈕。使用者如需再次學習，返回原本入口重新點擊「開始學習」。
- 中斷恢復：重新整理、關閉後重開、短暫離線或重新登入時，應盡可能恢復尚未完成的 Session，不重複扣除新卡額度、不重複提交同一次作答。
- 多裝置保護：保留既有版本驗證、正式事件紀錄、衝突偵測與復原機制，不得因同步或重試而靜默覆蓋有效學習記錄。

- **功能化偏好與字卡樣式**

偏好設定依實際功能分類為「一般」「字卡與學習」「資料與備份」，保留既有說明／關於入口，以及主題／語言快捷操作。

字卡樣式包含：

- 學習模式：排程模式／無盡模式。
- 排程方法：固定排程／FSRS。
- 單次複習上限：預設 100 張，可調整。
- 每日新卡上限：預設 20 張，可調整。
- 暫停引入新卡門檻：預設 200 張，可調整。

預設樣式與自訂樣式：

#### 構詞關聯與詞形變化：編輯與閱讀 UI（#42）
- 字典編輯主要區塊按「基本資料 → 義項 → 構詞關聯 → 詞形變化 → 其他既有內容」排列；非每個單字皆有的資料按需顯示。空白區塊只保留簡潔說明及「＋新增」，不預先展開成排空欄位。原「原始字形」文字輸入區由**詞形變化**區塷取代，不將舊自由文字自動認定為結構化詞形；既有資料須無損保留並處理相容性。
- **構詞關聯是詞條關聯，不是自由文字**：按「＋新增構詞關聯」開啟搜尋選擇器，查詢既有且可存取的 Word／Prefix／Root Entry，顯示拼寫、類型與義項資訊；有多義項時按資料契約選擇 Sense。保存為真實 `target_entry_id`／`target_sense_id`，不得用再次手打的文字代替 ID，也不得自動建立新詞條。
- 選定構詞關聯只需顯示目標詞條、必要的義項對應與更換／移除／排序操作；**不再要求或顯示關聯種類、查證狀態、查證說明三個欄位，目標資料模型亦不保留這三項作為構詞關聯屬性**。構詞關聯支援「**不分義項／詞條共用**」選項，以 `sense_id = null`（依實際欄位契約）表達，不必指定某一義項；**多義項新關聯預設為不分義項**，管理員可自行改選特定義項。只有單一義項時不顯示義項選擇器，採詞條共用／不分義項的預設即可，除非舊資料已有明確 Sense 指向，應保留該指向且不可靜默改寫。**義項選擇欄位只在管理員編輯介面可見（且僅多義項時顯示）；一般使用者閱讀頁不顯示管理用的義項選擇欄位**，只依實際關聯呈現構詞內容。提供查無結果、載入失敗、不合法及重複關聯的明確訊息。**只有查證完成的字典內容才允許公開發布**；查證屬發布前的編輯／審核責任，不藉由每條構詞關聯的查證欄位實現，且不得把拼字相似自動當作構詞證據。閱讀頁僅在有關聯時呈現，成分名稱可進入目標詞條／Sense，並保留反向查詢。
- **詞形變化是原詞條的附屬資料**：區分語法類型與詞形字串，依詞性提供適切選項，例如動詞過去式、過去分詞、第三人稱單數、現在分詞及名詞複數；可視情況歸屬相關詞性／Sense，新增、修改、移除和檢視多個形式。同形可合法對應多個不同語法類型，但不應產生完全相同的重複記錄。
- `walked`、`books`、`went`、`gone` **都不因詞形變化而建立獨立公開 Dictionary Entry**；它們應附屬於 `walk`、`book`、`go`。**#42 此階段只要求管理員手動維護詞形，暫不實作或要求自動規則推導**；未來若規劃自動推導及例外處理，另行確認需求，不得把推測詞形當成已發布事實。
- 閱讀頁只在有**已儲存的詞形資料**時呈現「類型：形式」的精簡列表／資訊格，例如 `go` 的「過去式：went」「過去分詞：gone」；詞形不顯示成獨立 Entry 連結。搜尋 `went`／`gone` 可在已有詞形資料時導向 `go`，搜尋 `walked`／`books` 同理；不因缺少詞形記錄而自動產生猜測結果，也不能隱藏同形詞或直接命中的合法詞條。
- 桌面可水平呈現構詞卡片並在過長時換行；行動版採單欄、易點選操作及適合手機的搜尋浮層。搜尋、選取、排序與對話框支援鍵盤、焦點還原和可讀取的錯誤狀態。欄位修改必須參與 #41 的 dirty／儲存／人工發布流程；相關資料庫、匯入匯出、舊資料與測試採非破壞性相容方案。

- 本階段詞形由管理員明確維護，依義項詞性提供類型；不猜測規則形式。編輯失敗時可下載目前輸入作為比對備份，再選擇儲存／放棄／繼續編輯及重新載入。原始字形以收合的相容註釋保留；CSV v1 不包含詞形，含詞形時須明確阻止不完整 CSV 匯出並提示完整 JSON 交換途徑。

#### 字首與字根分類
Prefix 共四類，主要分類設定於 Sense level，同一詞條家族的不同 Sense 可屬不同類別：

1. 性質、評價與否定
2. 位置、方向與關係
3. 數值、量與程度
4. 作用與變化

Root 共九類：

1. 空間、位置與環境
2. 動作、接觸與物理作用
3. 移動、轉變與方向
4. 物質、自然與元素
5. 生命、身體與感官
6. 情感、心理與意志
7. 心智、溝通與學習
8. 社會、法律與制度
9. 時間、狀態、數量與邏輯

Word 使用自身的詞條與義項分類方式。

#### 大量資料匯出、編輯、匯入與發布（#44）
- **操作目標**：大量新增或修改數百至數千筆單字時，不要求管理員自行切分多個小檔、反覆手動匯入或逐批發布；系統可在內部安全分批，但整體應由使用者一次啟動、確認及查看進度。平常單筆編輯維持原有 Nexus 後台操作。
- **匯出**：可依全部或篩選範圍取得可供大量修改且能安全重新匯入的資料。完整交換資料須保留 Entry／Sense／附屬記錄的穩定 ID、多義項、讀音、構詞 Entry／Sense 關聯、詞形變化、例句、詞源、學習內容及其他正式欄位；不支援完整往返的格式不可標示為「完整匯出」或靜默遺失資訊。
- **格式原則**：CSV、JSON 或其他格式都可評估，重點是大量編輯的便利性與無損往返；不強制使用者管理多份檔案或維持 GitHub 原始檔和 Supabase 的雙向同步。Supabase 保持正式字典資料來源，交換檔案不是第二套必須持續同步的字典。
- **匯入**：選擇檔案後自動檢查並呈現整體摘要；管理員一次確認即處理全部可安全匯入內容，不必先逐欄完成決策。疑義欄位常駐待審核，不阻止同詞條其他獨立的安全變更。未出現在檔案中的詞條或子項目**不得預設為刪除指令**，既有 ID、義項與未修改的資料須保留。具體規則依下方「安全自動匯入與常駐審核」。
- **執行及恢復**：系統自動分批完成寫入、顯示進度、成功／失敗／待審清單；中斷後可安全重試，避免重複建立或靜默覆寫。Published 內容變動必須走 Review Draft／核准流程，不因批次匯入直接公開。
- **發布全部草稿**：管理介面使用此明確文案；對整套字典全部可發布草稿作預覽及人工確認，**不受目前搜尋、分類、狀態篩選或分頁限制**。後端仍安全分批續行，阻擋、無效、版本變更的項目列出原因；保留暫停／刷新恢復／結果報告。歷史已保存的「篩選範圍發布」工作不可誤顯示成全域發布的恢復工作。已發布詞條的新版本仍須走個別 Review 核准，不能以此按鈕繞過。
- **完整交換格式決策**：`nexus-dictionary-exchange` schema_version 1 JSON，保留每筆完整 Snapshot、Entry／Sense／全部附屬 ID／版本／分類／構詞順序，active Review 原文及版本；新檔案內容未知欄位明確拒絕。Published 狀態、時間、revision、AI provenance 與 active Review 為比對資訊，不是直接寫入／公開指令；active Review 的更新必須沿用既有 Review 驗證服務及版本檢查，不靜默略過或覆蓋較新決策。現有讀音 `ipa`／locale／note 原樣保留，不自動猜測或轉換 KK／IPA。
- **匯出範圍**：全部或目前搜尋／類型／狀態篩選，以固定範圍的有界分頁取得單一檔案；顯示進度、失敗可重試。各詞條有包含內容及 active Review 的版本戳，範圍內任何影響 JSON 內容的 Entry、子項、分類、metadata 或 active Review 內容／狀態在匯出分頁期間改變時要求重匯出（不禁止同時編輯）；不把交換檔當作整個資料庫的歷史或帳號備份。
- **安全套用**：保留有效 stable IDs，明確且版本匹配的新增／修改一次確認後自動處理；Published 修改只建立 Review。既有 active Review 先比對其當前版本及內容，只將可獨立驗證的增量安全合併到同一 Review；同形歧義、非法欄位／關聯及版本衝突留給人工處理。不缺省刪除漏掉的詞條或子項目；省略構詞列時保留其既有排序位置，新增可使用預設空 provenance 的 metadata 指定構詞順序；檔案中只改分類／標籤或構詞順序也須正確判定與套用。
- **同裝置作業**：匯入 operation UUID 必須在發送前持久化；每批有界、自動續批、可停止未開始批次、掉回覆安全重試。刷新後提供恢復，不自動執行新的正式寫入。結果可下載成功／失敗／待審／未處理清單。發布沿用原預覽 token 與查證聲明，恢復不重新納入未曾確認的新草稿；過期或內容改變重新預覽。

#### 安全自動匯入與常駐審核（#16）

- **流程定位**：管理員匯入支援的 JSON／CSV／Markdown 時，解析後顯示檔案來源、總數及基本風險摘要，經一次匯入確認後自動處理可安全寫入的資料。匯入不要求逐筆完成歧義選擇，也不因少數疑義阻止其餘合法內容；可取消未開始批次、查看進度並下載結果。
- **只自動寫入安全內容**：必須確認 Entry／Sense／附屬資料 Stable ID、類型、所屬詞條、版本、合法欄位及關聯依賴；可確認的新增詞條、義項、詞形、關聯與不覆寫既有有效內容的補值，依既有資料規則匯入。重複來源內容不重複新增；已存在且相同者標示未變更。僅通過 Schema 不等於詞義已外部查證，詞形類型、義項歸屬等不得無證據猜測。
- **欄位層級部分套用**：同一詞條同時有安全修改與不明差異時，將獨立的安全修改寫入 Draft／Review Draft，而只將疑義內容保留待審核。彼此相依的 Sense、Inflection、Relation 必須作為有效的相依群組處理，不能產生孤立、無效或部分毀損的資料。Published 版本一律不因匯入直接覆寫或公開；修改已發布詞條應建立／更新安全的 Review Draft，保護既有 active Review、revision 與公開內容。
- **常駐疑義類型**：新增內容無法唯一對應既有義項或內容（如 `ambiguous_content`）、同 Stable ID 的值不同（`content_difference`）、既有與匯入分類不同（`category_difference`）、詞條共用與特定 Sense 歸屬不明（`shared_content_scope`）、可能重複的 Sense／Inflection／Relation、內容來源或語義可信度不足時，只保留受影響的差異供日後確認。`new_content` 與 `category_missing` 須依安全條件判斷，不能一律擋住，也不能一律接受。
- **禁止強制覆寫**：Stable ID 對應不同詞條類型（`identity_kind`）、內容 ID 屬於另一詞條（`identity_owner`）、同類同拼寫但不同 Entry ID（`homograph`）、無效結構（`invalid`）、版本衝突（`revision_conflict`）、預覽後版本改變（`preview_changed`），以及權限／參照完整性驗證不通過時，禁止不安全的自動合併與寫入。保留原因與安全重試／重新比對入口，不得自行編造或移動 ID。
- **管理清單三種主要工作狀態**：**🟢 新發布**＝有 Published 且沒有待發布草稿或未決匯入差異；**🟡 有草稿**＝尚未發布的 Draft 或 Review Draft（可同時已有公開版本）；**🔴 待審核**＝有尚未解決的匯入疑義或阻擋問題。顯示優先序為 🔴＞🟡＞🟢；它們是管理工作狀態，不能替代底層 Published／Draft／Review Draft。紅色詞條原有的 Published 仍正常公開；綠色不表示所有語義已查證。
- **管理列表**：顯示三色標記、各狀態可信總數、🔴 未解決差異數，支援狀態、類型及文字篩選與既有分頁。統計依唯一 Entry 計數，不因一筆詞條多個差異而重複計算。
- **詞條審核**：點擊 🔴 可查看匯入時間／來源、Entry／Sense、現有與候選內容、欄位差異、原因和相依群組。按差異安全限制提供「使用匯入版本」「保留現有」「新增獨立 Sense」「建立／更新 Review Draft」「暫不處理」「重新比對」等適用操作，不將全部選項無差別開放。
- **決策與實際套用區分**：選擇處理方法僅記錄決策，畫面須清楚區分「已決策但未套用」與「已套用」。提供「套用已決策項目」，只處理已完成決策且通過重新驗證的獨立欄位／相依群組；其他未決或「暫不處理」不阻擋安全項目。解決最後一項疑義後依目前草稿／發布狀態自動更新清單顏色。
- **常駐保存與跨裝置**：匯入差異、原始候選、目標、來源、版本、決策與套用結果受管理權限保護並持久化，刷新、登出再登入或換裝置都能繼續；不能只依賴瀏覽器本機 Session。一般讀者不可取得未發布內容或管理審核紀錄。
- **重複匯入及相容性**：重匯相同來源不得再次建立已套用項目或無限制複製未決差異；原始匯入 operation ID／版本／審計支援冪等重試與衝突重新比對，保留無損 JSON／備份格式契約。現有本機未完成匯入 Session（包含先前 6,301 筆匯入中已處理及待審部分）須提供非破壞性轉移／恢復方式；已套用內容不重做，本機資料核對成功前不得清除。匯入結果明確區分「已套用至 Draft」「已建立 Review Draft」「未變更」「待審核」「保留現有／拒絕」「失敗」。
- **與發布分離**：自動匯入、紅色差異解決和「發布全部草稿」是不同操作。發布仍由管理員另外確認並遵守既有查證、權限、版本與依賴檢查；不將未查證內容或待審差異自動公開。

#### 既有匯入資料核對（#12）
- 既有 13 份字典資料的匯入屬一次性歷史工作；使用者表示先前已匯入，須先對照保留的原檔、Entry／Sense ID 和正式 Supabase 內容，不能因舊任務未結案而重新匯入。

#### 詞條識別、義項與匯入規則

- 同一詞條類型（Word／Prefix／Root）中，忽略英文大小寫及詞頭、詞尾空白後，相同拼寫對應同一 Entry；不同類型可以存在相同拼寫的詞條。
- 一個 Entry 可包含多個 Sense，依詞性、繁體中文義項、歷史詞源與語意差異區分；字卡連結採穩定的 Entry ID，編輯及匯入時保留 Entry／Sense 識別。
- 詞性、中文釋義及僅適用特定意思的讀音、例句、詞源和記憶內容，歸屬相應 Sense；整個詞條通用的資訊可由 Entry 共用，管理端能辨別兩者。
- 支援一個詞條具有多筆讀音、音標系統（KK／IPA）、語言／地區標記，以及 Entry 共用或 Sense 專屬的讀音；現存 IPA 欄位的相容方式須在實作時核對。
- 匯入時，系統檢查重複詞條、義項對應、欄位與關聯有效性；無法確定的更新交由管理員審查，並保留其他義項內容。
- 匯入預覽提供可直接套用、需審查及無效資料的辨識結果；正式套用時重新核對資料版本、管理權限及衝突，並保留匯入紀錄與可安全重試能力。
- 詞形變化（例如 go／went／gone）與構詞衍生（例如 act／action／active）使用不同的關聯模型；具體操作與呈現依下列「構詞關聯與詞形變化」規格。


### F-SCORE — 製譜

### F-NOVEL — 小說

- **小說（F-NOVEL）**：作品總覽、章節、閱讀模式及閱讀設定。

- **入口與總覽**：`creative_type: novel` 開啟時先進入作品總覽：封面（PNG／JPEG／WebP，≤ 3 MB，實際附件保存與同步）、可編輯作品名稱、獨立概述（`NovelSettings.synopsis`，不得由正文自動推導）、字數／章節統計、完整目錄。
- **內容邊界（D-201）**：只有段落、H1、H2 與基本 inline 文字樣式；貼上一律轉純文字；不含表格、圖片、清單、提示框、程式碼、LaTeX。
- **章節（D-209）**：
  - 章節是獨立的 `pages` 記錄：`kind: "novel_chapter"`、`parent_id`＝作品 ID、`sort_order`、標題、正文、建立／更新時間；繼承 `owner_id` RLS、同步、tombstone 與備份。
  - **啟用章節工作區時**才把舊單篇正文轉存為章節並清空作品正文；不啟用則不動舊資料（`NovelSettings.chaptersEnabled` 只由明確、交易式啟用寫入）。
  - 目錄、上一章／下一章、刪除、排序、重新命名皆操作獨立章節；重新命名與排序保留章節 ID。
  - **翻頁**：章與章之間透過**頂部與底部**的「上一章／選章／下一章」切換，不再把各章放在同一流動頁的前後區塊。

  - 登入後預設選取項目時會排除章節（`novelChapters.ts` 的 preferred 邏輯）。
- **閱讀設定**：`NovelSettings.theme`（parchment／cream／eye_care／dark／pure_white）、`fontSize`（14–26）、`fontFamily`（serif／sans／kai）、`lineHeight`（1.6–2.4）、`paragraphIndent`、`showWordCount`。
- **手機**：目錄為覆蓋式面板；閱讀／編輯主區獨立垂直捲動。
- **驗收**：`tests/novelChapters.test.cjs`；隔離瀏覽器測試（桌面與 390×844）通過；正式帳號同步未測。

### F-CHARACTER — 角色卡

- **角色卡（F-CHARACTER）**：結構化區塊、混合內容、分頁及自訂模板。

- **資料真相**：`Page.character_data`（`CharacterProfileData`）；`basic`（姓名、別名、頭像、性別、年齡、角色、所屬、名言、自訂欄位）＋`sections[]`＋`tabs[]`。
- **區塊與內容（D-210）**：使用者可加「區塊」（`type: "group"`），區塊內可放多筆「內容」（`contents[]`），每筆內容有標題與一種資料類型。舊的單一類型區塊（葉節點）維持可讀可編輯。
- **資料類型（程式碼型別 `CharacterComponentType`）**：`group`、`key_value`、`rich_text`、`tags`、`stats`、`rating`、`relations`、`radar`、`palette`、`tendency`、`statistics`、`gallery`、`links`、`music`。對應使用者所稱的長文（`rich_text`，檢視時預設收合，可點三角形展開）、雷達圖（可新增細項，實際繪圖）、評分、偏向、統計、色票（可新增細項）、相冊、連結、音樂（只存外部連結）；「短文」與 `key_value` 的對應**未核實**。
- **統計**：每列有三格內容——短文字、長文字（多行介紹）、數值（可含單位）；欄位頂部有可自訂小標（`statisticHeaders`）；會把所有細項數值加總（測試例：37 + 5 = 42）。
- **分頁**：一張角卡可加多頁（類似試算表底部切換），用於補充資訊（例如 D&D 法術、攜帶物品）。原 `sections` 為「基本資料」分頁；分頁列位於底部；可新增、重新命名、排序、刪除（刪除有確認，取消不變動）。
- **外觀**：組件標題不使用 emoji（型別仍保留 `icon` 欄位但 UI 不顯示）。
- **模板（D-210）**：
  - 建立時選擇模板；既有角色卡可依後述「新版定案」安全套用同一模板的新版本，不代表可任意無損更換不同模板。
  - 內建：空白（完全無區塊、無填寫內容）、D&D 5e、CoC 7e（各自專用欄位與補充頁；只是記錄格式，**不是規則計算器**）；另保留 `fantasy`／`modern` 型別值供舊資料。
  - 使用者可透過「儲存為模板」建立僅含結構的私人模板；管理與更新以後述新版定案為準。
  - 舊 `example`／`basicExamples` 屬歷史相容資料；新版建立及複製模板不攜帶角色內容、範文、數值或照片。
  - 自訂模板資料與帳號歸屬保留既有相容性；模板頁不出現在一般角色卡清單。新版模板更新與已建立角色卡的安全套用以後述「新版定案」為準。
  - 從模板建立時複製區塊與分頁結構並產生新 ID（`instantiateCharacterTemplate`）。
- **驗收**：`tests/characterWorkspace.test.cjs`；隔離瀏覽器：混合區塊、統計加總、長文收合、分頁管理、存模板／建角色、重新載入保留。

- 可為角色卡儲存及套用模板；模板更新保留既有角色資料。
- 頭像及相簿附件與角色資料建立關聯。

#### 角色卡閱覽畫面與欄位呈現
- 角色卡區分「編輯表單」與「角色卡閱覽」兩種模式。編輯模式提供輸入、刪除、增減內容、區塊與分頁管理；閱覽模式應將已填寫資料呈現成可閱讀的角色檔案，不展示只用於編輯的操作按鈕與輸入控制項。
- 基本資料區可呈現姓名、別名、頭像、性別、年齡、角色、所屬、名言及自訂欄位；自訂欄位以使用者設定的名稱／內容顯示，並與內建欄位並存。
- 內容以具標題的區塊組織，區塊可包含多筆不同型態的內容；支援單欄或雙欄呈現，窄螢幕回落單欄。長文在閱覽時可展開／收合，且應保留段落換行。
- 角色卡的各補充分頁可在頁面底部切換；切換只改變目前閱覽的資料群組，不改寫其他分頁內容。角色資料、區塊及補充頁在重新開啟後須保留。
- 雷達圖至少有三個維度才繪製；每個維度顯示名稱、數值與上限。統計類內容依欄位顯示項目、文字介紹、數量、單位重量及總重，並呈現總數量、總重量；詳細欄名及顯示格式可以再核准，不應只顯示原始 JSON。
- 評分、偏向、色票、相簿、角色關係及外部連結等內容，各自使用適合閱讀的視覺方式；閱覽模式中的數值及資料不得因切換模式而更動。現有偏向尺度採中點 50，編輯時靠近中點可吸附；是否固定作為產品規則尚待核准。
- 編輯／閱覽的控制項位置、空欄位隱藏方式、手機閱覽排列及模板範文是否顯示，需再依使用者確認，不將現行元件的偶然樣式升格成永久規格。

#### 角色卡 UI／區塊與組件新版定案（2026-10-15，取代上方舊式編輯／閱覽描述）

- **正式術語**：「區塊」是具標題、負責組織內容的容器；「組件」是區塊內承載文字、統計、關係、雷達、圖片等資料的單位。保留兩種名稱與層級，不再混用。
- **開啟即預覽**：開啟角色卡直接顯示可閱讀的內容，**取消整頁的「編輯表單／檢視表單」切換**。每個可編輯組件右上角有扳手圖示，點擊後開啟類似 Keep 記事的浮動組件編輯視窗；點「儲存並返回」或點遮罩皆自動儲存並關閉。資料驗證失敗或保存失敗時不得靜默關閉／遺失修改，需留在視窗顯示錯誤與重試。
- **組件尺寸與流動排列**：每個一般組件右下角有三斜線三角形控制柄，可調長寬但**不能透過縮放壓縮字體**，僅改變內容顯示範圍；過量內容可在組件內捲動或展開，不能截斷遺失資料。組件依剩餘寬度**自動流動補位**，同列最多三個，窄畫面減少並排數；具體最小／最大尺寸由實作者依觸控與可讀性訂定並測試。區塊本身不另設獨立尺寸調整，大小隨內部組件決定。**移除「兩欄檢視」功能／開關**。
- **特殊角色基本資料區塊**：選用時永遠固定於角色卡最頂端並獨占整個區塊，不與其他組件並排、不參與拖曳、不可調整尺寸；固定僅有**照片、名字、年齡、性別、種族**五項，不支援自訂加欄（其他資訊放一般組件）。可編輯五項內容；允許刪除整個基本資料區塊並於「新增區塊」選單重新加入；最多存在一個，重新加入自動置頂，已有時不顯示重複新增。
- **新增一般區塊**：先點「新增區塊」，輸入名稱並產生**空區塊**，不在這一步強制選組件；再透過區塊內的「＋新增組件」選擇類型與編輯。空區塊保留標題、位置、ID，顯示「尚無組件」及「＋新增組件」，可接受拖入的組件；不能因最後一個組件被移走而自動刪除。
- **組件拖曳**：在觸控裝置稍微長按組件即可拖曳（建議約 300ms，可依誤觸測試調整），支援區塊內排序及**跨一般區塊移動**，移動時即時預覽補位，放開後自動保存歸屬及排序；原資料、尺寸與設定不變。右下尺寸柄與右上扳手不得觸發排序；滑鼠、鍵盤及觸控需有合適操作方式。角色基本資料不接受其他組件移入。
- **區塊排序**：長按**一般區塊標題**開始拖曳；拖曳期間**所有區塊暫時縮成只顯示標題**以方便排序；放開後儲存區塊順序並恢復先前的展開狀態。基本資料區塊始終固定於頂端，不參與排序。
- **刪除**：刪除一般組件由其扳手編輯浮窗發起，需確認；刪除空的一般區塊可直接完成；刪除含組件的區塊須確認，明確警告**會連內部組件一起刪除**，不額外提供刪區塊但自動保留組件的流程。各種刪除須遵守帳號、同步及現有可恢復性規範。

#### 角色卡模板與創作資源庫新版定案（2026-10-15）

- **資源庫邊界**：創作資源庫與學習集資源庫為**各自獨立功能入口及管理介面**，不合併為共用總資源庫。創作資源庫內先選「角色卡／世界觀」，再以「全部／官方／投稿」篩選；只有管理員可發布／標註官方，一般使用者發布為投稿，**投稿即公開，不經事前審核**，管理員保留檢舉處理及下架權限。世界觀的模板資源庫採同一發布、版本與下載治理原則；世界觀編輯器細節仍以 F-WORLD 為基礎，不將角色基本資料強套到世界觀。
- **從角色卡建立私人模板**：只能由**既有角色卡**在「⋯ → 儲存為模板」建立初始模板，儲存時**僅保留區塊名稱與順序、組件類型／名稱、欄位結構、尺寸與排版**；所有角色文字、姓名、性別、年齡、種族、照片／相簿與個人數值皆不得帶入。新建角色卡可選空白、官方或已下載／自己的模板，新卡是獨立資料。
- **模板管理與編輯**：創作功能有獨立**模板管理頁**，可預覽、重新命名、複製、刪除私人模板並管理投稿；模板首次由角色卡產生，但**既有模板允許在模板管理內直接編輯**結構／排版，沿用區塊與組件的互動，不必再從角色卡重建。私人模板修改自動儲存。
- **投稿與版本**：公開投稿保留固定模板身分／連結、作者、累積下載數及**不可覆寫的歷史發布版本**；作者在獨立草稿編輯，自動保存草稿，**只有主動「發布新版」才替換公開版本**。允許捨棄草稿，或由**任意歷史發布版本**建立新草稿；覆蓋現有草稿前要確認。歷史版本可供查看、作者回復／衍生草稿，**一般使用者只能下載當前最新版**。
- **下載／更新**：下載模板形成使用者可管理的個人模板副本，已建立的角色卡與原發布版本相互獨立；原作者發布新版後，個人模板顯示**有可用更新**，由使用者手動確認後以新版**取代下載模板**，不自動更新。既有角色卡也不自動更動。
- **在已建立角色卡安全套用同來源新版本**：修正舊規則「模板只可建立時套用」——允許使用者**手動選擇更新目前綁定的模板版本**，不清除已輸入的角色資料；基於穩定模板區塊／組件識別碼匹配，安全套用新排版、同組件改名／移動及新增空組件。新版本刪除的舊組件或類型不相容的內容，不得刪除或強制轉換，應移入角色卡底部的**「保留內容」區塊**，仍可編輯或拖曳；用戶自行修改過的尺寸、順序、名稱等不得無條件覆蓋，需合併／保護。更新前保留可還原的角色卡快照；操作須具交易式失敗回滾／完整保留原狀，禁止部分覆蓋或遺失資料。與**完全不同模板間的更換**尚未決定，不應視為本功能範圍。
- **發布撤回**：作者可**下架**（可重新上架，保留版本、連結、下載統計）或**永久刪除投稿**（二次確認後移除該投稿與公開版本歷史，不可恢復）；兩者均**不得刪除他人已下載的獨立副本或已建立角色卡**。來源永久刪除後，已下載副本不再有來源更新。
- **二次投稿權限**：投稿者可設定是否允許別人基於此模板公開改編版，**預設不允許**；下載、私人修改、用以建立角色卡不受影響。允許時改編投稿須標註原作者／來源模板並保留來源關係；作者可隨時修改權限，但只影響**未來新投稿**，不追溯下架此前合法發布的改編作品。保留發布時的權限／來源快照，供追溯。
- **實作邊界**：公開投稿、版本、草稿、下載、改編來源及角色卡模板套用需有正式 owner／RLS、資料完整性與相容規則；不藉 UI 更新直接改動正式資料庫。上線 migration／實際生產資料異動須另取得使用者授權，保留既有角色卡及模板資料。

### F-WORLD — 世界觀

- **世界觀（F-WORLD）**：結構化世界觀資料，角色可歸屬世界觀或獨立建立。

- **規格**：`creative_type: "world"`，沿用角卡的區塊／內容／分頁／模板機制，可進行設定與描寫。
- **歸屬**：角色以 `character_data.world_id` 歸屬某世界觀，或為空表示獨立角色。
- **邊界**：世界觀／人物／地點與**小說**的關聯明確不做（D-201）。
- **待確認**：使用者原話為「類似角卡，也可以進行設定與描寫」；現況是否已足夠、是否需要世界觀專用內建模板，尚無明確要求。

### F-UTILITY — 網頁與工具（計數／抽選）

- **網頁收藏（F-WEB）**：介紹資訊與連結清單編輯；公開展示另行設計。
- **計數（F-COUNTER）**：項目計數、依群組名稱彙總；階層群組設計待確認。
- **抽選（F-DRAW）**：項目庫、標籤篩選與抽選指定數量。

三者共用 `UtilityView`，資料存在 `Page.content_json`（D-218），皆為**基礎版**。

- **網頁（F-WEB）**：`intro`（介紹）＋`links[]`（`{id, label, url}`）。使用者要求「類似 lit.link」：**對外展示頁、版面設計、公開網址均未做**（依賴 M8-0／M8-1）。
- **計數（F-COUNTER）**：`counters[]`（`{id, name, value, group?}`）。「大組」以文字欄 `group` 表示，介面依名稱加總並顯示各組合計與全部合計；空的 group 顯示「未分組」。使用者原意是「一個計數項目可分大組與小組，大組是小組總和，小組可單獨存在」——**正式的大組物件與階層 UI 尚待資料模型確認**（M10-8）。
- **抽選（F-DRAW）**：`draws[]`（`{id, label, tags[]}`）；一個抽選項目 = 一個資料庫；單筆可多標籤（逗號分隔輸入）；抽取時勾選標籤，候選為**同時具備所有勾選標籤**者，再隨機抽指定數量。使用者要求的「某標籤抽幾個」「標籤配標籤」等規則**尚未做**（M10-9）。
- **新增選單**：三個功能各有對應新增項（網頁／計數項目／抽選資料庫）。
- **工具為獨立功能而非分類標籤**：導航層級以「工具」作為一個頂層功能，內含「計數」及「抽選」兩個子功能；不再於頂層功能導覽中將計數、抽選視為與工具平行的功能，也不得僅把工具實作為普通檔案分類／篩選器。點開「工具」進入正式工具首頁，再選擇內部的計數或抽選（依 PR #63 後續修正）。保留既有計數／抽選頁面、資料型別、內容、直達連結與返回來源。
- **工具的建立入口**：在工具範圍中提供「新增計數項目」「新增抽選資料庫」等對應操作；其他全域建立入口可保留直接建立的捷徑，但其導航與功能歸屬需一致。

#### 收藏、計數與抽選擴充

- 網頁收藏可整理介紹與連結清單，公開展示頁的網址、權限和版型待核准。
- 計數可依群組名稱彙總數值；大組／小組層級與調整方式待核准。
- 抽選可依標籤篩選並選取指定數量；各標籤分別抽 N 個、標籤組合與去重規則待核准。

### F-PAGEFORMAT — Flow、A4 與簡報格式

- **Flow**：Note 預設流動內容；流動格式不被自動改成分頁。
- **A4**：固定 A4 210mm × 297mm；自動分頁、內文可寫到底部、頁碼置中顯示。
- **Presentation**：16:9／4:3 由 Presentation 使用；Note 不應因此被當作簡報。
- **Document**：偏 A4；可依既有格式規則選擇 flow／A4／custom。
- **Custom**：⚠️ 有型別預留，但尺寸、行為與列印規格尚未形成完整 contract。
- **已知限制**：目前自動分頁仍有估算高度啟發式；表格、圖片、複雜內容需未來 DOM measurement 改善。

#### 全站排序選單單項切換方向（2026-10-15，#34）

#### 共用介面原則

- 頁面操作保持清楚、可預期；需要輸入或確認的操作優先使用頁面內對話框。
- 桌面、平板與手機保持主要操作可觸達，側欄／彈窗依裝置寬度調整呈現。
- **各功能項目預覽**：所有有項目集合的功能頁（如筆記、文檔、字卡學習集、簡報、創作內容、網頁、計數、抽選等）都提供可用的**卡片／預覽檢視**，不局限於筆記功能。依內容類型呈現有意義且安全的摘要／縮圖、名稱及必要的更新資訊；沒有可預覽內容時提供名稱與類型等合理替代，而非空白卡片。不要求所有資料類型顯示相同的預覽細節。可保留既有列表檢視與切換方式，檢視模式不改變資料。
- **項目更多操作**：每個項目在列表與卡片模式皆提供獨立的「⋯」操作選單，至少在該項目適用的情況下支援**重新命名、複製、刪除**；依資料類型與權限顯示其他既有操作。卡片主體用於開啟／預覽，點「⋯」不得誤觸開啟項目；操作完成後保持清單搜尋、篩選、排序及頁面上下文。
- **操作安全與一致性**：刪除需有明確確認，遵守現有回收桶、軟刪除及權限規則；複製產生新的合法 ID／資料關聯，不複製不可繼承的學習排程事件、審核身分、公開發布狀態或敏感權限。重新命名不改變原項目 ID 與引用連結。若某資料類型不支援某項操作，應清楚停用或不顯示，不提供無效選項；桌面滑鼠、觸控裝置及鍵盤皆能使用選單。

#### 共用列表分頁與頁碼跳轉（#49）

- 對所有使用「上一頁／下一頁＋當前頁碼」的**分頁列表／搜尋結果**，統一顯示「第 X 頁／共 Y 頁」；不要把筆記 A4 頁碼、角色卡自訂分頁或簡報頁面誤套這套列表導覽規則。
- 分頁列只保留「上一頁　 第 X 頁／共 Y 頁　下一頁」；**不顯示鉛筆圖示、說明文案、前往按鈕或額外確認按鈕**。直接點擊數字 X 即原位編輯，按 Enter（手機鍵盤的完成／確認）即驗證並跳轉；Esc 取消並保持原頁。
- 空白、非整數、負數、0、超出總頁數、無法解析的值均不可觸發跳轉，**保持原本頁數且不改變列表內容**。重新顯示的頁碼應為目前實際頁數，不可以默默改跳首頁／最後一頁。
- 當結果總數未由 API 提供時，不可假造「共 Y 頁」；先檢查後端分頁契約並取得可信總頁數，或於功能支援前保留原有分頁顯示。
- 頁碼跳轉需配合現有篩選／排序／搜尋條件及非同步載入狀態，防止競態回應覆蓋較新的頁面；無障礙支援鍵盤操作、數字輸入標籤、行動版觸控。
- 已確認空列表統一顯示「第 0 頁／共 0 頁」，上下頁與頁碼編輯停用；有效頁碼範圍仍由 1 開始。資料更動讓原頁不存在時，轉到新的最後有效頁；搜尋／篩選變更一般回首頁。這與無效輸入留在原頁的規則分開處理。
- 載入新頁時保留同條件下最近一次成功頁面；顯示載入狀態、允許再確認其他有效頁碼，以最後確認的請求為準。失敗保留原頁及內容，提供重試。分頁本身不增加其他操作按鈕。
