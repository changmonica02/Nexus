# Nexus — 產品規格（使用者畫面與操作契約）

## 工作區元件整理與儲存回饋（Refs #85）
- 主／副／單視窗沿用相同內容分派與附件載入契約，保留各自頁面、操作與分割控制。
- 編輯器僅在本機持久化成功後顯示「已儲存至此裝置」；雲端同步狀態獨立。等待寫入顯示儲存中、失敗保留內容並提供重試；Ctrl/Cmd+S 執行所在編輯器的實際儲存，不以計時器模擬成功。
- 共用彈窗與選單基礎，保留既有焦點、Escape、busy、背景點擊及工具列選取行為。功能分類與資料權限不變。
- 未接入的舊學習畫面／建立 registry／側欄偏好可退場；歷史 Quiz、資料恢復契約、Inbox 未決需求與匯入 fallback 保留。

> 以功能模組為單位，描述使用者從何處進入、看見哪些 UI、如何操作、可以修改哪些設定，以及操作後的結果。未確認的尺寸、手勢、預設值與流程標示「待核准」。產品歷史記於 [HISTORY](HISTORY.md)，程式修改與驗收狀態記於 [HANDOFF](HANDOFF.md)，技術及資料庫設計記於 [ARCHITECTURE](ARCHITECTURE.md)。

## 文件閱讀方式
- 各 `F-*` 章節是產品需求主要來源；同一功能的入口、畫面、操作、設定與資料集中紀錄。
- 精確 UI 位置、順序、大小、間距、導覽、狀態和跨裝置差異，一旦確認即寫入所屬模組，不另建立重複總表。
- 使用者未設定而ai自行設定的規格也要紀錄於此，方便後續的調整

### F-NOTE — 筆記

實作追蹤：#87（2026-10-19；分批驗證，未完成項以 HANDOFF 為準；本輪不部署）。

#### 功能定位與入口
- **最新產品方向（2026-10-19）**：筆記採單一、連續、無紙張限制的自由區塊編輯；只有在列印／PDF 匯出預覽時才進行 A4 分頁。先前「流動／分頁筆記」新建分流、編輯中固定 A4 紙張及「依 A4 整理分頁」屬待淘汰的舊行為，不再是新筆記的目標。既有分頁筆記及手動分頁內容須完整保留，如何無損顯示／轉換須先驗證；不得逕行清除舊資料。
- 筆記沿用現有富文字編輯器及工作區，可製作一般筆記、課堂整理、題庫與講義；從首頁、筆記列表及新增入口進入。保留資料夾、子頁拖曳、搜尋、備份、自動儲存、離線與跨裝置同步。

#### 編輯畫面與導覽
- 頂部操作列靠左依序排列側欄開關、返回按鈕與筆記標題；右側顯示儲存狀態及其他操作。標題過長時不擠壓操作。常用編輯工具清楚分組，設定面板不長期佔用編輯空間。
- 桌面筆記側欄可展開／收合，**像 Notion 一樣拖曳邊界調整寬度**，並記住上次寬度與開合狀態；開合與調寬後，筆記使用剩餘空間且保留游標、捲動位置與尚未儲存內容。手機以可關閉浮層呈現，不壓縮編輯區。筆記頁面此行為優先於下方舊「全站一律浮動側欄」描述；其他功能的側欄策略不因本次需求更動。
- 右上角「⋯ → 外觀與版面配置 → 全寬」提供獨立開關：關閉時內容以適中閱讀寬度置中，開啟時利用編輯區可用寬度且保留邊距；**逐篇筆記記住設定**。側欄寬度與全寬開關彼此獨立，均不改變列印紙張尺寸。
- 依標題產生可點選跳轉的文件目錄；目錄可獨立展開／收合。日常編輯不固定顯示 A4 頁面縮圖。桌面、平板與手機均有可操作的編輯入口。

#### Notion 式區塊與多欄
- 每個區塊提供新增入口及六點拖曳把手；支援拖曳排序、多選、複製、移動、刪除、復原、斜線插入與把手選單「轉換成」（文字、標題、清單、待辦、引用、摺疊等）。轉換必須保留可相容內容，不可靜默遺失。
- 可在**指定內容區域**建立雙欄，不把整篇筆記改成雙欄；支援把手拖曳、轉換選單或斜線指令建立，欄內可容納文字、公式、表格、圖片及摺疊等內容。拖曳欄間分隔線可調比例，區塊可移入／移出，整組可複製、移動、刪除與復原。三欄及更多欄位的擴充細則待確認。
- 摺疊區塊可包含其他支援區塊，編輯時自由展開／收合；狀態不得造成內容遺失。

#### Obsidian 式 LaTeX 公式
- 在一般段落使用 `$...$` 直接輸入**行內公式**，與文字同行且無永久框線；使用 `$$...$$` 建立**獨立公式**。非編輯時顯示數學排版，游標進入或點選時直接編輯 LaTeX 原文，離開後恢復渲染，不強制開啟獨立視窗。
- 行內及獨立公式均可選取、複製、貼上、剪下、刪除與復原；正在編輯公式時刪除鍵優先修改原文，不得意外移除整個公式；清空後可移除空公式區塊，不留下無法刪除的輸入框。
- 支援跳脫美元符號、未完成輸入及錯誤語法提示；出錯時保留原文。儲存可再次編輯的 LaTeX 內容，不以渲染圖片取代；既有公式須相容。

#### 筆記內容與題目工具
- 保留段落、標題、文字樣式、清單、引用、連結、待辦、表格、提示框、程式碼、圖片／圖說、標籤、資料夾及頁面關聯；既有表格與貼上功能繼續運作。
- 題目、選項、解答、解析及作答留白是**通用筆記區塊**，可與一般文字、圖片、公式、表格交錯。題目與選項支援調整順序、自動編號及必要的編輯／匯出功能；起始題號、巢狀編號、選項排列及留白預設高度等細節仍待確認。
- 定義、例題、練習、重點等教學區塊保留擴充能力；標題目錄在增刪標題後更新，跨區塊參照更新規則待確認。

#### 唯讀表格分頁（2026-10-25；Refs #107）
- PR #108 實作與驗證狀態見 HANDOFF／NOTE-EDITOR-AUDIT；尚未合併，不代表全部跨頁場景已完成。
- 第二批只在輸出副本按安全列邊界延續表格，重複可識別表頭；跨列合併儲存格以完整相連列群組保留，不切斷 rowspan／colspan。
- 單列、合併群組或巢狀／複雜表格無法安全拆分時，保留原內容並警告；不假裝已完整處理。舊手動 pageBreak 只在輸出副本映射換頁，不刪改原節點。
- 長雙欄維持原比例／DOM 語意並警告，最終跨頁閱讀順序仍未定案；不自行轉為單欄。用同一合成文件比較原生 CSS、隔離 Paged.js 與唯讀 DOM；Paged.js 不加入正式依賴。

#### 匯出預覽安全與資源就緒（2026-10-24；Refs #105）
- 僅在唯讀輸出副本等待圖片／字型就緒後量測；資源失敗、超時、內容超出紙張或目前無法可靠分割時，提供清楚警告，不靜默裁切或宣稱頁數精確。重試／取消及儲存失敗不得改寫正式內容。
- 保留現有紙張與版面設定；修正列印時工作區佔位及副本的可編輯控制，不修改 Note JSON、schema、附件或同步契約。長雙欄跨頁順序、分頁調整保存等既有待決規則維持未決。

#### 匯出預覽、A4 分頁及列印
- 「匯出／列印」先進入**獨立預覽**，預設 A4，提供紙張方向、邊界、頁首頁尾、頁碼及分頁檢查；分頁只屬輸出排版，不把筆記原始內容拆成一頁頁獨立資料。輸出 PDF 應與預覽一致。
- 匯出時**所有摺疊內容預設展開**，但不修改編輯器內原有的收合狀態。局部雙欄盡量依原比例並排，過寬先重新排版／合理調整，不得直接裁切文字、公式、圖片或表格；長雙欄跨頁的閱讀順序尚待核准。
- 支援預覽中的手動分頁調整；這些調整僅作用於此次匯出，或保存為文件列印設定的規則**待確認**，在確認前不得覆寫原筆記。過寬內容的縮放與換頁細節待確認。
- 保留 PDF 列印、Nexus JSON／工作區備份及適用的 Markdown 匯出，不破壞完整可編輯資料。

#### 資料安全、驗收與待決事項
- 區塊與公式的編輯、模式／寬度調整及匯出預覽不得導致資料遺失；保留既有文件、附件、同步、離線與復原功能，不因文字排版變動重複上傳／下載無關附件。
- **必要驗收**：①自由連續編輯無 A4 紙張；②把手拖曳與轉換、刪除復原；③局部雙欄建立與調寬；④摺疊輸出完整且原狀態不變；⑤`$...$`／`$$...$$` 可編輯、可刪除且無殘留空框；⑥文件標題靠左，側欄可收合及拖曳調寬且記住狀態；⑦單篇全寬設定生效；⑧A4 預覽與 PDF 一致；⑨舊筆記、附件、離線與跨裝置同步不受破壞。
- **待決**：長雙欄跨頁順序、匯出分頁調整是否保存、超寬內容的輸出規則、三欄擴充與舊分頁筆記的無損過渡細則。未決事項不得由實作者自行當作已核准產品決策。

### F-DOCUMENT — Plain Document

- **文檔（F-DOCUMENT）**：純文字與 Markdown 導向的文件編修和匯入匯出。

- **目的**：適合文章、報告、正式文字與 Markdown 工作流。
- **編輯模式**：`plain` editor variant；不承擔 Note 的 rich typography 工具列。
- **格式**：以 flow／A4／custom 為主；Document 預設 A4 的目前規則見 F-PAGEFORMAT。
- **匯出**：Markdown；需在 export 前 flush save。
- **定位**：Document 為純文字／Markdown 導向的獨立編輯流程，Note 為富文字筆記編輯流程。

#### 文件匯入與匯出

- 使用者可將 `.md`、`.markdown`、`.txt` 匯入為 Document；匯出 Markdown 前保存當前編輯內容。

### F-PDF — PDF 文件與研究筆記

- **PDF 研究（F-PDF）**：PDF 匯入、檢視、附檔及關聯研究筆記；進階 PDF 工作空間待細化。

#### PDF 匯入與 Research Note

```
選擇本地 PDF
→ 建立 Attachment metadata
→ 寫入 binary
→ 自動建立 Research Note Page
→ attachment_ids / primary_attachment_id 關聯
→ 顯示 PDF viewer 與研究筆記
```

- PDF binary 不放入 `content_json`；以 attachment／asset 管理。
- 附件同步（Refs #84）：先讀 owner-scoped metadata 與伺服器 revision；本機已驗證同版本時完整內容下載為 0。首次／新裝置、版本變更或快取損壞才下載，下載期間重新核對版本；舊無版本快取需一次重驗。帳號隔離、刪除標記、未上傳本機內容與離線功能優先；跨分頁合併下載，失敗可重試。同帳號憑證刷新不重建引擎，背景降低同步頻率、回前景檢查變更。既有 revision 也可能因 metadata 修改而遞增，此時允許保守重驗該附件，不重抓其他附件。
- 一篇 PDF 對一篇主 research note 是起步 UX，不是資料模型硬限制。
- Viewer 現有 Open、Small/Medium/Large、Hide/Show、loading/unavailable/normal 三態。

#### PDF 文件工作空間（待定案）

- **使用者要求**：PDF 應以「匯入」形式進入 Nexus，形成類似 GoodNotes 的 PDF 文件工作空間，而不是把 PDF 視為一般 rich-text insert。

- **相容性**：PDF 文件工作空間與 Attachment／Research Note 的既有資料及操作流程相容。

#### PDF 匯入與文件整理

- 使用者選取 PDF，系統建立附件並開啟關聯的 Research Note 與 PDF viewer；進階 PDF 文件工作空間的手寫、註解及頁面操作待核准。

F-STUDY — 學習集與字卡

本次改版追蹤：#47；以下產品契約取代舊 #47／#48 的 50 張上限與非正式額外練習規則。

1. 開始學習

- 統一入口：點擊「開始學習」建立 Study Session，使用者先回想字卡對應的答案，再點擊「查看答案」，根據記憶狀況選擇「熟記／知道／困難／忘記」。
- 正式學習：所有正式作答皆記錄作答時間、選項、字卡狀態及排程結果，並依目前選用的排程方法計算下一次到期時間（due）。
- 學習設定：開始 Session 時讀取該學習集目前套用的字卡樣式。進行中的 Session 保留建立時的設定，不因使用者修改樣式而突然改變學習規則。

2. 單次名額與每日新卡

- 單次複習上限：每次開始學習，預設最多選入 100 張不同字卡，包含新卡與複習卡，可由使用者調整。此上限僅適用於當次 Session，不是每日複習總上限；本批完成後，使用者可再次從「開始學習」入口建立下一批。
- 每日新卡上限：每個學習集預設每天最多引入 20 張新卡，可由使用者調整。每日新卡額度為同一學習集當日所有 Session 共用，不因重新開始學習而重置。
- 每日換日：依使用者裝置當地日期，於 00:00 切換學習日並刷新每日新卡額度。不需要在午夜自動建立 Session；下次開始學習時依當日額度選取新卡。
- 新卡計數：新卡首次正式呈現時，使用 "introduce" 事件扣除當日新卡額度。僅預先選入 Session、載入或預覽字卡，不視為正式引入。
- 暫停新卡門檻：當學習集中目前已到期、尚待複習的舊卡數量達到設定門檻（預設 200 張）時，停止引入新卡，但仍依目前學習模式安排舊卡。當已到期舊卡數量低於門檻時，恢復引入新卡，仍須遵守當日剩餘新卡額度。
- 門檻計算：已到期舊卡包含符合到期條件的 Review、Learning、Relearning 不同字卡，不包含尚未到期的舊卡及未引入的新卡。同一張卡只計算一次。
- 名額計算：同一張字卡在同一 Session 中只占用一個不同字卡名額。因短間隔 Learning／Relearning 而再次出現，不重複占用名額。

3. 排程模式與無盡模式

兩種模式均為正式學習，使用相同的字卡記錄、排程方法、每日新卡額度及單次複習上限。兩者唯一的抽卡差異，是是否允許提前選取尚未到期的舊卡。

- 正常排程模式：依目前排程選取已到期舊卡及當日符合條件的新卡，不提前抽取尚未到期的舊卡。正常候選不足單次上限時，以實際可選數量建立 Session。
- 無盡模式：先依正常排程規則選取已到期舊卡及符合條件的新卡。僅當正常候選不足單次上限時，才依到期時間由近至遠，提前選取尚未到期的已學卡補足名額。
- 強制解凍限制：無盡模式只從尚未排入當次 Session 的合格舊卡補位，不重複抽取同一張卡。如果整個學習集符合條件的不同字卡少於單次上限，則以實際可選數量建立 Session，不強制重複抽卡。
- 正式評分：無盡模式提前複習的字卡仍屬正式複習；作答後必須記錄結果，依目前排程方法和實際作答時間重新計算 due，不保留舊 due 假裝沒有作答。
- 暫停新卡門檻：兩種模式都遵守暫停新卡門檻。達到門檻後仍優先安排已到期舊卡；只有無盡模式在正常候選不足時可以提前抽取未到期舊卡。
- 不設額外練習流程：無盡模式直接從「開始學習」入口啟動，不需要先完成正常排程，也不是不更新正式排程的獨立練習功能。

4. 固定排程

固定排程由使用者設定四種回答選項的間隔，作答後按照所選間隔計算下一次到期時間，不由 FSRS 動態決定。

一般複習（Review）的預設間隔：

回答選項| 預設間隔
熟記| 7 天
知道| 3 天
困難| 1 小時
忘記| 5 分鐘

新卡（New）與重新學習（Relearning）的預設間隔：

回答選項| 預設間隔
熟記| 4 天
知道| 1 天
困難| 10 分鐘
忘記| 1 分鐘

固定排程狀態轉換：

- New／Relearning → Review：選擇「熟記」或「知道」後，進入一般複習狀態，並依本次回答的對應間隔安排 due。下次作答使用一般複習的時間設定。
- New／Relearning 維持學習：選擇「困難」或「忘記」時，維持當前學習／重新學習狀態，依對應短間隔安排下一次出現。
- Review 維持複習：選擇「熟記」「知道」或「困難」時，維持 Review 狀態，依一般複習間隔更新 due。
- Review → Relearning：選擇「忘記」時，進入重新學習狀態，本次依一般複習的「忘記」間隔（預設 5 分鐘）安排下一次出現；下一次作答開始使用 New／Relearning 的四種回答間隔。

時間設定與紀錄：

- 固定排程中的各回答間隔可以透過字卡樣式修改，不限制為預設值。
- 按鈕顯示依目前卡片狀態及樣式設定計算的實際預計間隔。
- 每次正式作答都保存當時採用的排程方法、回答選項、實際作答時間和計算結果，供後續同步、歷史查詢及排程切換使用。

5. FSRS 排程

- 演算法：沿用 Nexus 現有的 FSRS-6，依每張字卡的歷史作答紀錄、記憶穩定度、難度及實際複習時間，動態計算下一次到期時間。
- 回答對應：「熟記／知道／困難／忘記」分別對應 FSRS 的 Easy／Good／Hard／Again。
- 預計間隔：回答按鈕顯示依 FSRS 即時計算的預計間隔，而非固定排程設定值。
- 新卡與重新學習：保留符合 FSRS 的 Learning／Relearning 狀態與短間隔機制；短間隔到期時依實際時間安排再次作答。
- 無盡模式相容：提前抽取尚未到期的舊卡時，使用其當前 FSRS 狀態及實際作答時間正式評分，更新記錄與 due。
- 排程完整性：不得為了填滿單次名額而直接修改未作答字卡的 due，或偽造複習事件。

6. 排程方法切換與歷史保護

- 可切換方法：字卡樣式可選擇固定排程或 FSRS，兩種方法與正常排程／無盡模式獨立，可以自由組合。
- 保留歷史：切換排程方法不得刪除既有作答事件、字卡記錄、引入日期、學習進度或版本資訊，也不得將已學卡直接重置為 New。
- 狀態隔離：固定排程與 FSRS 使用各自適用的排程狀態，不得把固定間隔直接當成 FSRS 記憶穩定度或難度參數。
- 安全轉換：切換排程方法時，需依現有作答歷史與可用資料採用明確、可重現的狀態轉換策略。無法可靠轉換的資料不得自行推測或偽造歷史，應採取安全且可追溯的相容處理。固定排程期間保留原 FSRS 記憶狀態；回切後以該狀態及真實作答時間計算，不把固定作答偽裝為 FSRS 歷史。沒有可靠 FSRS 記憶的已學卡保留目前進度與 due，於下一次真實 FSRS 作答建立記憶狀態，並記錄此相容轉換。
- 生效時機：新排程方法適用於之後建立的 Session；尚未完成的 Session 繼續使用建立時的設定。
- 資料同步：排程方法、狀態及切換結果必須與既有離線、跨裝置同步和衝突處理機制相容。

- **Session 完成、等待與恢復**

- 學習進度：學習中顯示本次已完成的不同字卡數、總名額及必要的學習進度。
- 短間隔等待：已選入 Session 的 Learning／Relearning 字卡，如下一次作答時間尚未到期，應顯示等待狀態，而非直接宣告本次完成。
- 短間隔續作：已開始的短間隔卡片到期後，仍需完成必要作答；同一卡再次出現不重複占用單次名額。
- 完成條件：當本次所有必要的正式學習步驟完成後，Session 才可標記完成。
- 完成畫面：僅顯示「恭喜你完成這次學習」，不在完成畫面提供開始下一批或切換模式的續接按鈕。使用者如需再次學習，返回原本入口重新點擊「開始學習」。
- 中斷恢復：重新整理、關閉後重開、短暫離線或重新登入時，應盡可能恢復尚未完成的 Session，不重複扣除新卡額度、不重複提交同一次作答。
- 多裝置保護：保留既有版本驗證、正式事件紀錄、衝突偵測與復原機制，不得因同步或重試而靜默覆蓋有效學習記錄。

- **功能化偏好與字卡樣式**

偏好設定依實際功能分類為「一般」「字卡與學習」「資料與備份」，保留既有說明／關於入口，以及主題／語言快捷操作。

字卡樣式包含：

- 學習模式：排程模式／無盡模式。
- 排程方法：固定排程／FSRS。
- 單次複習上限：預設 100 張，可調整。
- 每日新卡上限：預設 20 張，可調整。
- 暫停引入新卡門檻：預設 200 張，可調整。
- 複習卡排序：最早到期／FSRS 低可回想率／隨機。低可回想率排序僅對具有可計算 FSRS 記憶狀態的卡片適用；其他卡片須採穩定的相容排序規則。
- 固定排程回答時間：分別設定新卡、重新學習及一般複習的「熟記／知道／困難／忘記」間隔。

預設樣式與自訂樣式：

- 系統提供一套「預設字卡樣式」，所有未指定其他樣式的學習集皆使用此樣式。

- 使用者可指定每個學習集套用哪一套樣式。
- 樣式以學習集為套用單位，而不是每張字卡各自指定。
- 自訂樣式的優先度高於預設樣式。指定後使用該自訂樣式的完整設定，不與預設樣式逐欄混用。
- 同一套自訂樣式可供多個學習集使用。修改該樣式後，所有套用它的學習集在後續新建 Session 時使用更新後的設定。
- 修改樣式不得直接重設字卡進度、作答歷史、排程狀態或既有 due；如果涉及排程方法切換，須遵守排程轉換與歷史保護規則。
- 已開始但尚未完成的 Session 保留建立時的有效設定，不因預設樣式或自訂樣式變更而突然改變規則。
- 舊設定相容：已儲存的學習設定值保留為完整移轉樣式，顯示提示；不猜測舊值是否來自預設或使用者自訂。未設定者使用新預設；使用者可明確改用預設樣式。未含完整快照的舊 Session 保留已知的原 FSRS 方法、模式及名額，凍結可取得的舊設定並顯示相容提示，不宣稱重建缺失的歷史快照。



- **既有卡片資料相容**：使用者可預覽、確認字卡英文與中文內容，再使用統一學習流程；欄位不完整的字卡仍可保存，且僅內容完整的卡片進入出題。
- **編輯與複製**：中文修改保留排程；英文修改提供保留／重設／取消（重設以新 generation＋`reset` 事件，歷史仍保留）；單卡與整個學習集複製只複製內容並建立 New 卡；刪除為 soft delete。
- **雙裝置衝突**：兩台裝置離線回答同一張卡時，保留所有事件，標記 `conflict` 並停止該卡正式排程；使用者須明確選擇「保留歷史並重新學習」。不自動推測語義合併。

#### 構詞關聯與詞形變化：編輯與閱讀 UI（#42）
- 字典編輯主要區塊按「基本資料 → 義項 → 構詞關聯 → 詞形變化 → 其他既有內容」排列；非每個單字皆有的資料按需顯示。空白區塊只保留簡潔說明及「＋新增」，不預先展開成排空欄位。原「原始字形」文字輸入區由**詞形變化**區塷取代，不將舊自由文字自動認定為結構化詞形；結構化資料、Stable ID 與歷史保留；已確認淘汰的舊原始字形註釋依下述安全移除契約退場。
- **構詞關聯是詞條關聯，不是自由文字**：按「＋新增構詞關聯」開啟搜尋選擇器，查詢既有且可存取的 Word／Prefix／Root Entry，顯示拼寫、類型與義項資訊；有多義項時按資料契約選擇 Sense。保存為真實 `target_entry_id`／`target_sense_id`，不得用再次手打的文字代替 ID，亦不得根據查詢自行猜測並自動建立新詞條；管理員明確確認的快速建立流程依本節最小詞條發布契約實作，須遵守前述發布與去重約束。
- 選定構詞關聯只需顯示目標詞條、必要的義項對應與更換／移除／排序操作；**不再要求或顯示關聯種類、查證狀態、查證說明三個欄位，目標資料模型亦不保留這三項作為構詞關聯屬性**。構詞關聯支援「**不分義項／詞條共用**」選項，以 `sense_id = null`（依實際欄位契約）表達，不必指定某一義項；**多義項新關聯預設為不分義項**，管理員可自行改選特定義項。只有單一義項時不顯示義項選擇器，採詞條共用／不分義項的預設即可，除非舊資料已有明確 Sense 指向，應保留該指向且不可靜默改寫。**義項選擇欄位只在管理員編輯介面可見（且僅多義項時顯示）；一般使用者閱讀頁不顯示管理用的義項選擇欄位**，只依實際關聯呈現構詞內容。提供查無結果、載入失敗、不合法及重複關聯的明確訊息。**只有查證完成的字典內容才允許公開發布**；查證屬發布前的編輯／審核責任，不藉由每條構詞關聯的查證欄位實現，且不得把拼字相似自動當作構詞證據。閱讀頁僅在有關聯時呈現，成分名稱可進入目標詞條／Sense，並保留反向查詢。
- **詞形變化是原詞條的附屬資料**：區分語法類型與詞形字串，依詞性提供適切選項，例如動詞過去式、過去分詞、第三人稱單數、現在分詞及名詞複數；可視情況歸屬相關詞性／Sense，新增、修改、移除和檢視多個形式。同形可合法對應多個不同語法類型，但不應產生完全相同的重複記錄。
- `walked`、`books`、`went`、`gone` **都不因詞形變化而建立獨立公開 Dictionary Entry**；它們應附屬於 `walk`、`book`、`go`。**#42 此階段只要求管理員手動維護詞形，暫不實作或要求自動規則推導**；未來若規劃自動推導及例外處理，另行確認需求，不得把推測詞形當成已發布事實。
- 閱讀頁只在有**已儲存的詞形資料**時呈現「類型：形式」的精簡列表／資訊格，例如 `go` 的「過去式：went」「過去分詞：gone」；詞形不顯示成獨立 Entry 連結。搜尋 `went`／`gone` 可在已有詞形資料時導向 `go`，搜尋 `walked`／`books` 同理；不因缺少詞形記錄而自動產生猜測結果，也不能隱藏同形詞或直接命中的合法詞條。
- 桌面可水平呈現構詞卡片並在過長時換行；行動版採單欄、易點選操作及適合手機的搜尋浮層。搜尋、選取、排序與對話框支援鍵盤、焦點還原和可讀取的錯誤狀態。欄位修改必須參與 #41 的 dirty／儲存／人工發布流程；相關資料庫、匯入匯出、舊資料與測試採非破壞性相容方案。

- 本階段詞形由管理員明確維護，依義項詞性提供類型；不猜測規則形式。編輯失敗時保留目前輸入，離開前可選擇儲存／放棄／繼續編輯；需要時重新開啟詞條確認伺服器內容。不再提供舊原始字形註釋；CSV v1 不包含詞形，含詞形時須明確阻止不完整 CSV 匯出並提示完整 JSON 交換途徑。

#### 字首與字根分類
Prefix 共四類，主要分類設定於 Sense level，同一詞條家族的不同 Sense 可屬不同類別：

1. 性質、評價與否定
2. 位置、方向與關係
3. 數值、量與程度
4. 作用與變化

Root 共九類：

1. 空間、位置與環境
2. 動作、接觸與物理作用
3. 移動、轉變與方向
4. 物質、自然與元素
5. 生命、身體與感官
6. 情感、心理與意志
7. 心智、溝通與學習
8. 社會、法律與制度
9. 時間、狀態、數量與邏輯

Word 使用自身的詞條與義項分類方式。

#### 大量資料匯出、編輯、匯入與發布（#44）
- **操作目標**：大量新增或修改數百至數千筆單字時，不要求管理員自行切分多個小檔、反覆手動匯入或逐批發布；系統可在內部安全分批，但整體應由使用者一次啟動、確認及查看進度。平常單筆編輯維持原有 Nexus 後台操作。
- **匯出**：可依全部或篩選範圍取得可供大量修改且能安全重新匯入的資料。完整交換資料須保留 Entry／Sense／附屬記錄的穩定 ID、多義項、讀音、構詞 Entry／Sense 關聯、詞形變化、例句、詞源、學習內容及其他正式欄位；不支援完整往返的格式不可標示為「完整匯出」或靜默遺失資訊。
- **格式原則**：CSV、JSON 或其他格式都可評估，重點是大量編輯的便利性與無損往返；不強制使用者管理多份檔案或維持 GitHub 原始檔和 Supabase 的雙向同步。Supabase 保持正式字典資料來源，交換檔案不是第二套必須持續同步的字典。
- **匯入**：選擇檔案後自動檢查並呈現整體摘要；管理員一次確認即處理全部可安全匯入內容，不必先逐欄完成決策。疑義欄位常駐待審核，不阻止同詞條其他獨立的安全變更。未出現在檔案中的詞條或子項目**不得預設為刪除指令**，既有 ID、義項與未修改的資料須保留。具體規則依下方「安全自動匯入與常駐審核」。
- **執行及恢復**：系統自動分批完成寫入、顯示進度、成功／失敗／待審清單；中斷後可安全重試，避免重複建立或靜默覆寫。Published 內容變動必須走 Review Draft／核准流程，不因批次匯入直接公開。
- **發布全部草稿**：管理介面使用此明確文案；對整套字典全部可發布草稿作預覽及人工確認，**不受目前搜尋、分類、狀態篩選或分頁限制**。後端仍安全分批續行，阻擋、無效、版本變更的項目列出原因；保留暫停／刷新恢復／結果報告。歷史已保存的「篩選範圍發布」工作不可誤顯示成全域發布的恢復工作。已發布詞條的新版本仍須走個別 Review 核准，不能以此按鈕繞過。
- **完整交換格式決策**：`nexus-dictionary-exchange` schema_version 1 JSON，保留每筆完整 Snapshot、Entry／Sense／全部附屬 ID／版本／分類／構詞順序，active Review 原文及版本；新檔案內容未知欄位明確拒絕。Published 狀態、時間、revision、AI provenance 與 active Review 為比對資訊，不是直接寫入／公開指令；active Review 的更新必須沿用既有 Review 驗證服務及版本檢查，不靜默略過或覆蓋較新決策。現有讀音 `ipa`／locale／note 原樣保留，不自動猜測或轉換 KK／IPA。
- **匯出範圍**：全部或目前搜尋／類型／狀態篩選，以固定範圍的有界分頁取得單一檔案；顯示進度、失敗可重試。各詞條有包含內容及 active Review 的版本戳，範圍內任何影響 JSON 內容的 Entry、子項、分類、metadata 或 active Review 內容／狀態在匯出分頁期間改變時要求重匯出（不禁止同時編輯）；不把交換檔當作整個資料庫的歷史或帳號備份。
- **安全套用**：保留有效 stable IDs，明確且版本匹配的新增／修改一次確認後自動處理；Published 修改只建立 Review。既有 active Review 先比對其當前版本及內容，只將可獨立驗證的增量安全合併到同一 Review；同形歧義、非法欄位／關聯及版本衝突留給人工處理。不缺省刪除漏掉的詞條或子項目；省略構詞列時保留其既有排序位置，新增可使用預設空 provenance 的 metadata 指定構詞順序；檔案中只改分類／標籤或構詞順序也須正確判定與套用。
- **同裝置作業**：匯入 operation UUID 必須在發送前持久化；每批有界、自動續批、可停止未開始批次、掉回覆安全重試。刷新後提供恢復，不自動執行新的正式寫入。結果可下載成功／失敗／待審／未處理清單。發布沿用原預覽 token 與查證聲明，恢復不重新納入未曾確認的新草稿；過期或內容改變重新預覽。

#### 安全自動匯入與常駐審核（#16）

- **流程定位**：管理員匯入支援的 JSON／CSV／Markdown 時，解析後顯示檔案來源、總數及基本風險摘要，經一次匯入確認後自動處理可安全寫入的資料。匯入不要求逐筆完成歧義選擇，也不因少數疑義阻止其餘合法內容；可取消未開始批次、查看進度並下載結果。
- **只自動寫入安全內容**：必須確認 Entry／Sense／附屬資料 Stable ID、類型、所屬詞條、版本、合法欄位及關聯依賴；可確認的新增詞條、義項、詞形、關聯與不覆寫既有有效內容的補值，依既有資料規則匯入。重複來源內容不重複新增；已存在且相同者標示未變更。僅通過 Schema 不等於詞義已外部查證，詞形類型、義項歸屬等不得無證據猜測。
- **欄位層級部分套用**：同一詞條同時有安全修改與不明差異時，將獨立的安全修改寫入 Draft／Review Draft，而只將疑義內容保留待審核。彼此相依的 Sense、Inflection、Relation 必須作為有效的相依群組處理，不能產生孤立、無效或部分毀損的資料。Published 版本一律不因匯入直接覆寫或公開；修改已發布詞條應建立／更新安全的 Review Draft，保護既有 active Review、revision 與公開內容。
- **常駐疑義類型**：新增內容無法唯一對應既有義項或內容（如 `ambiguous_content`）、同 Stable ID 的值不同（`content_difference`）、既有與匯入分類不同（`category_difference`）、詞條共用與特定 Sense 歸屬不明（`shared_content_scope`）、可能重複的 Sense／Inflection／Relation、內容來源或語義可信度不足時，只保留受影響的差異供日後確認。`new_content` 與 `category_missing` 須依安全條件判斷，不能一律擋住，也不能一律接受。
- **禁止強制覆寫**：Stable ID 對應不同詞條類型（`identity_kind`）、內容 ID 屬於另一詞條（`identity_owner`）、同類同拼寫但不同 Entry ID（`homograph`）、無效結構（`invalid`）、版本衝突（`revision_conflict`）、預覽後版本改變（`preview_changed`），以及權限／參照完整性驗證不通過時，禁止不安全的自動合併與寫入。保留原因與安全重試／重新比對入口，不得自行編造或移動 ID。
- **管理清單三種主要工作狀態**：**🟢 新發布**＝有 Published 且沒有待發布草稿或未決匯入差異；**🟡 有草稿**＝尚未發布的 Draft 或 Review Draft（可同時已有公開版本）；**🔴 待審核**＝有尚未解決的匯入疑義或阻擋問題。顯示優先序為 🔴＞🟡＞🟢；它們是管理工作狀態，不能替代底層 Published／Draft／Review Draft。紅色詞條原有的 Published 仍正常公開；綠色不表示所有語義已查證。
- **管理列表**：顯示三色標記、各狀態可信總數、🔴 未解決差異數，支援狀態、類型及文字篩選與既有分頁。統計依唯一 Entry 計數，不因一筆詞條多個差異而重複計算。
- **詞條審核**：點擊 🔴 可查看匯入時間／來源、Entry／Sense、現有與候選內容、欄位差異、原因和相依群組。按差異安全限制提供「使用匯入版本」「保留現有」「新增獨立 Sense」「建立／更新 Review Draft」「暫不處理」「重新比對」等適用操作，不將全部選項無差別開放。
- **決策與實際套用區分**：選擇處理方法僅記錄決策，畫面須清楚區分「已決策但未套用」與「已套用」。提供「套用已決策項目」，只處理已完成決策且通過重新驗證的獨立欄位／相依群組；其他未決或「暫不處理」不阻擋安全項目。解決最後一項疑義後依目前草稿／發布狀態自動更新清單顏色。
- **常駐保存與跨裝置**：匯入差異、原始候選、目標、來源、版本、決策與套用結果受管理權限保護並持久化，刷新、登出再登入或換裝置都能繼續；不能只依賴瀏覽器本機 Session。一般讀者不可取得未發布內容或管理審核紀錄。
- **重複匯入及相容性**：重匯相同來源不得再次建立已套用項目或無限制複製未決差異；原始匯入 operation ID／版本／審計支援冪等重試與衝突重新比對，保留無損 JSON／備份格式契約。現有本機未完成匯入 Session（包含先前 6,301 筆匯入中已處理及待審部分）須提供非破壞性轉移／恢復方式；已套用內容不重做，本機資料核對成功前不得清除。匯入結果明確區分「已套用至 Draft」「已建立 Review Draft」「未變更」「待審核」「保留現有／拒絕」「失敗」。
- **與發布分離**：自動匯入、紅色差異解決和「發布全部草稿」是不同操作。發布仍由管理員另外確認並遵守既有查證、權限、版本與依賴檢查；不將未查證內容或待審差異自動公開。

#### 詞條識別、義項與匯入規則

- 同一詞條類型（Word／Prefix／Root）中，忽略英文大小寫及詞頭、詞尾空白後，相同拼寫對應同一 Entry；不同類型可以存在相同拼寫的詞條。
- 一個 Entry 可包含多個 Sense，依詞性、繁體中文義項、歷史詞源與語意差異區分；字卡連結採穩定的 Entry ID，編輯及匯入時保留 Entry／Sense 識別。
- 詞性、中文釋義及僅適用特定意思的讀音、例句、詞源和記憶內容，歸屬相應 Sense；整個詞條通用的資訊可由 Entry 共用，管理端能辨別兩者。
- 支援一個詞條具有多筆讀音、音標系統（KK／IPA）、語言／地區標記，以及 Entry 共用或 Sense 專屬的讀音；現存 IPA 欄位的相容方式須在實作時核對。
- 匯入時，系統檢查重複詞條、義項對應、欄位與關聯有效性；無法確定的更新交由管理員審查，並保留其他義項內容。
- 匯入預覽提供可直接套用、需審查及無效資料的辨識結果；正式套用時重新核對資料版本、管理權限及衝突，並保留匯入紀錄與可安全重試能力。
- 詞形變化（例如 go／went／gone）與構詞衍生（例如 act／action／active）使用不同的關聯模型；具體操作與呈現依下列「構詞關聯與詞形變化」規格。


### F-SCORE — 製譜

- **製譜（F-SCORE）**：作品管理、簡譜、五線譜與吉他譜的預覽及編輯工作流。

- **C2 已確認先前順序**：先作品管理＋快速簡譜，再各自開發五線譜與吉他譜；三者不強制互轉，也不預設共用同一完整音樂資料模型。正式譜面 preview 優先，進入「編輯」才顯示文字源碼；桌面可探索分割畫面，手機以預覽／編輯切換為主。
- **候選簡譜草案（未最終確認）**：`_6`／`^6` 表八度、`#5`／`b7` 升降、`6•` 附點、`5/`／`5//` 時值、`0` 休止、`|` 小節；標頭 `@title`／`@key`／`@time`／`@tempo`，註解 `//` 屬草案，不直接當 parser 合約。播放與完整 MusicXML／MIDI 互轉非首版承諾。

### F-PRESENTATION — 簡報

- **簡報（F-PRESENTATION）**：投影片畫布、物件移動與縮放、旋轉、圖層排序、圖表與投影片導覽。

- **待細化能力**：對齊吸附、旋轉物件縮放、群組與鎖定、母片、圖表、復原與重做。

- **驗收**：畫布物件 reload/sync 後位置與內容正確，且真實瀏覽器互動通過。
- **畫布互動**：物件中心可拖曳移動，邊緣可調整大小；圖層可排序，圖表可調整顯示選項。

#### 物件操作與匯出

- 支援投影片、物件移動／縮放／旋轉、層級排序、圖表與投影片導覽；吸附、群組、鎖定、母片及匯出格式細節待核准。

#### 投影片預覽、縮圖與畫布閱覽
- 簡報工作區以目前選取的投影片為主要畫布，旁邊提供可收合的投影片縮圖列表；縮圖應預覽投影片內容及物件層次，而非只顯示標題。點選縮圖切換目前投影片，清除前一張投影片的物件選取狀態。
- 投影片清單提供新增、複製、刪除及選取操作；複製的投影片保留內容與排版但具有獨立識別，刪除不得在僅剩最後一張投影片時清空整份簡報。
- 縮圖、中央畫布與實際儲存內容應一致；移動、縮放、旋轉及調整圖層後，縮圖與畫布應更新，重新開啟仍能還原。
- 圖表的編輯區應能同時辨識圖表類型、設定、預覽及資料；修改圖表選項時，預覽應反映實際成品。圖表編輯是作品內容的操作，不等同整份簡報的播放／放映模式。
- 簡報另需明確區分「編輯畫布」、「無編輯控制項的預覽／放映」及「投影片縮圖」；**獨立全螢幕放映、鍵盤切換、手機手勢及播放控制等細節尚待核准，不應因程式碼未做便移除這類產品方向**。

### F-QUICKNOTE — Quick Notes

- **隨手記（F-QUICKNOTE）**：卡片式快速筆記與整理。

- **資料**：隨手記是獨立內容類型，卡片可設定顏色，搜尋、備份與帳號同步涵蓋其內容。

#### 任務檢視

### F-CREATIVE — Creative 入口

- **創作入口（F-CREATIVE）**：角色卡及世界觀等創作工具入口，小說有獨立入口。

- **資料方向**：Page shell + `kind: "creative"`；以 `creative_type` 區分 `novel`／`character`／`world`。
- **入口**：小說設有獨立功能入口；創作入口提供角色卡與世界觀，相關範本以「模板」命名。
- **判斷函式**（`types.ts`）：`isCreativeCharacterPage`＝creative 且（`character`／`world`／有 `character_data`）；`isNovelPage`＝creative 且非角色類。早期沒有 `creative_type` 的舊小說以此相容。

### F-NOVEL — 小說

- **小說（F-NOVEL）**：作品總覽、章節、閱讀模式及閱讀設定。

- **入口與總覽**：`creative_type: novel` 開啟時先進入作品總覽：封面（PNG／JPEG／WebP，≤ 3 MB，實際附件保存與同步）、可編輯作品名稱、獨立概述（`NovelSettings.synopsis`，不得由正文自動推導）、字數／章節統計、完整目錄。
- **內容邊界（D-201）**：只有段落、H1、H2 與基本 inline 文字樣式；貼上一律轉純文字；不含表格、圖片、清單、提示框、程式碼、LaTeX。
- **章節（D-209）**：
  - 章節是獨立的 `pages` 記錄：`kind: "novel_chapter"`、`parent_id`＝作品 ID、`sort_order`、標題、正文、建立／更新時間；繼承 `owner_id` RLS、同步、tombstone 與備份。
  - **啟用章節工作區時**才把舊單篇正文轉存為章節並清空作品正文；不啟用則不動舊資料（`NovelSettings.chaptersEnabled` 只由明確、交易式啟用寫入）。
  - 目錄、上一章／下一章、刪除、排序、重新命名皆操作獨立章節；重新命名與排序保留章節 ID。
  - **翻頁**：章與章之間透過**頂部與底部**的「上一章／選章／下一章」切換，不再把各章放在同一流動頁的前後區塊。
  - 章節頁不出現在一般頁面清單、Dashboard、右側面板、Command Palette（`NexusApp` 以 `kind !== "novel_chapter"` 過濾）。
  - 登入後預設選取項目時會排除章節（`novelChapters.ts` 的 preferred 邏輯）。
- **閱讀設定**：`NovelSettings.theme`（parchment／cream／eye_care／dark／pure_white）、`fontSize`（14–26）、`fontFamily`（serif／sans／kai）、`lineHeight`（1.6–2.4）、`paragraphIndent`、`showWordCount`。
- **手機**：目錄為覆蓋式面板；閱讀／編輯主區獨立垂直捲動。
- **驗收**：`tests/novelChapters.test.cjs`；隔離瀏覽器測試（桌面與 390×844）通過；正式帳號同步未測。

### F-CHARACTER — 角色卡

- **角色卡（F-CHARACTER）**：結構化區塊、混合內容、分頁及自訂模板。

F-CHARACTER — 角色卡功能規格

1. 基本結構

角色卡採用「分頁 → 區塊 → 組件」三級結構。

1.1 分頁

* 支援新增、重新命名、排序及刪除。
* 分頁切換列固定於角色卡底部。
* 原有內容歸於「基本資料」分頁。
* 刪除分頁須確認，取消後不變動。
* 各分頁可獨立管理區塊與組件。

1.2 區塊

* 區塊具有標題，可包含多個不同類型的組件。
* 點擊「新增區塊」後輸入名稱，建立空白區塊，不強制新增組件。
* 透過區塊內「＋新增組件」選擇組件類型。
* 空區塊保留原有位置，顯示「尚無組件」及「＋新增組件」。
* 移走最後一個組件不會自動刪除區塊。
* 區塊尺寸由內部組件決定，不提供獨立尺寸調整。

1.3 組件

* 每個組件具有標題、內容與對應的編輯功能。
* 同一區塊可混合不同類型的組件。
* 支援自訂尺寸、排序及跨一般區塊移動。
* 組件標題不顯示 Emoji 圖示。

2. 角色基本資料

提供專用的「角色基本資料區塊」。

固定欄位： 照片、姓名、年齡、性別、種族。

* 永遠固定於角色卡最頂端，獨占整列。
* 不可拖曳、調整尺寸或新增自訂欄位。
* 五項內容皆可編輯。
* 每張角色卡最多存在一個。
* 可刪除整個區塊，並透過「新增區塊」重新加入。
* 重新加入時自動置頂，已有時不顯示重複新增選項。
* 不接受其他組件移入。

3. 組件類型

類型	功能
群組	組織相關資訊
鍵值資料	成對記錄名稱與內容
長文	多行文字，預設收合，可展開
標籤	記錄多個文字標籤
數值	記錄角色能力與數值
評分	呈現不同項目的評分
人物關係	記錄角色間的關係
雷達圖	可新增細項並繪製圖表
色票	可新增多個顏色細項
偏向	呈現角色的特質傾向
統計	文字、說明及數值統計
相冊	收錄多張圖片
連結	保存外部連結
音樂	保存外部音樂連結

3.1 統計組件

* 每列包含：短文字、長文字、數值。
* 三欄皆有可自訂的欄位標題。
* 長文字支援多行內容。
* 數值可包含單位。
* 自動加總所有細項數值。

3.2 特殊規則

* 長文： 閱讀時預設收合，點擊三角形展開。
* 雷達圖： 支援新增細項，依數值實際繪圖。
* 色票： 支援新增多個顏色細項。
* 音樂： 僅保存外部連結，不保存音樂檔案。
* 短文： 是否與鍵值資料為同一類型尚待確認。

4. 閱讀與編輯

4.1 閱讀模式

* 開啟角色卡直接顯示完整排版內容。
* 移除整頁的「編輯／檢視」模式切換。
* 每個可編輯組件右上角顯示扳手圖示。

4.2 組件編輯

* 點擊扳手開啟浮動編輯視窗，互動形式類似 Google Keep。
* 點擊「儲存並返回」或視窗外遮罩，自動儲存並關閉。
* 驗證或儲存失敗時，保留視窗及修改內容，顯示錯誤並允許重試。
* 刪除組件由編輯視窗發起，須再次確認。

5. 排版與尺寸

5.1 尺寸調整

* 一般組件右下角具有三斜線尺寸控制柄。
* 可自由調整組件長寬。
* 調整尺寸不得縮放文字大小。
* 超出範圍的內容必須可捲動或展開，不得截斷遺失。
* 組件最小與最大尺寸須兼顧觸控操作及可讀性。

5.2 自動排列

* 組件依剩餘空間自動流動補位。
* 同列最多三個組件。
* 窄畫面自動減少並排數量。
* 調整尺寸或移動組件時，即時重新排列。
* 移除原有「兩欄檢視」功能及開關。

6. 拖曳與排序

6.1 組件拖曳

* 長按組件即可拖曳，觸控長按時間暫定約 300ms。
* 支援區塊內排序及跨一般區塊移動。
* 拖曳時即時預覽補位，放開後自動儲存。
* 移動後保留原內容、尺寸及設定。
* 扳手及尺寸控制柄不得誤觸發排序。
* 支援滑鼠、鍵盤與觸控操作。

6.2 區塊排序

* 長按一般區塊標題啟動拖曳。
* 拖曳期間所有區塊暫時收合至僅顯示標題。
* 放開後儲存順序，並恢復原先展開狀態。
* 基本資料區塊固定頂端，不參與排序。

7. 刪除規則

* 一般組件： 從編輯視窗刪除，須確認。
* 空白區塊： 可直接刪除。
* 含組件的區塊： 須確認，並明確警告內部組件將一併刪除。
* 不提供刪除區塊時自動保留內部組件的流程。
* 刪除操作須符合既有權限與資料復原規範。

⸻

8. 角色卡模板

8.1 模板種類

建立角色卡時可選擇：

* 空白模板： 不包含任何區塊或內容。
* D&D 5e： 專用欄位與補充分頁。
* CoC 7e： 專用欄位與補充分頁。
* 私人模板： 使用者自行建立的模板。
* 下載模板： 從創作資源庫取得的模板。

D&D 5e 與 CoC 7e 僅提供資料記錄格式，不包含規則計算器。

保留既有奇幻、現代類型角色卡的相容性。

8.2 建立私人模板

* 僅能由既有角色卡透過「⋯ → 儲存為模板」建立初始模板。
* 模板僅保留：
    * 區塊名稱及順序。
    * 組件類型及名稱。
    * 欄位結構。
    * 組件尺寸及排版。
* 不保留姓名、年齡、性別、種族、文字、照片、相冊圖片、個人數值或任何已填寫內容。
* 以模板建立的新角色卡為獨立內容，不隨模板自動修改。

8.3 模板管理

創作功能提供獨立的模板管理頁。

支援：

* 預覽、重新命名、複製、刪除私人模板。
* 直接編輯既有模板的結構及排版。
* 使用與角色卡相同的區塊、組件編輯方式。
* 私人模板修改自動儲存。
* 管理使用者自己的公開投稿。

模板不顯示於一般角色卡清單。

⸻

9. 創作資源庫

9.1 資源分類

* 創作資源庫與學習集資源庫維持獨立入口及管理介面。
* 創作資源庫分為「角色卡」與「世界觀」。
* 各類別提供「全部／官方／投稿」篩選。

9.2 發布權限

* 僅管理員可發布或標註官方資源。
* 一般使用者發布的資源歸類為投稿。
* 投稿立即公開，不需事前審核。
* 管理員保留檢舉處理及下架權限。
* 世界觀模板適用相同的發布、版本、下載及改編規則，但保留獨立的編輯結構。

10. 投稿與版本管理

10.1 公開投稿

每個投稿保留：

* 固定模板身分與連結。
* 作者資訊。
* 累積下載次數。
* 不可覆寫的歷史發布版本。

10.2 草稿與發布

* 已公開模板透過獨立草稿進行修改。
* 草稿修改自動儲存，不影響公開版本。
* 點擊「發布新版」才更新公開內容。
* 可捨棄未發布草稿。
* 可由任意歷史發布版本建立新草稿。
* 覆蓋現有草稿前須確認。
* 作者可查看歷史版本並據此重新編輯。
* 一般使用者僅能下載目前最新的正式版本。

11. 模板下載與更新

11.1 下載

* 下載後建立可獨立管理的私人模板副本。
* 可私人編輯，並用於建立角色卡。
* 下載副本及已建立的角色卡不受來源模板修改直接影響。

11.2 模板更新

* 原作者發布新版後，下載模板顯示「有可用更新」。
* 使用者手動確認後，以新版取代下載的模板。
* 不自動更新私人模板或既有角色卡。

11.3 已建立角色卡套用新版

允許角色卡手動更新目前綁定的同來源模板版本。

更新時：

* 保留所有已填寫的角色資料。
* 安全套用新版排版、原組件改名或移動、新增空組件。
* 保護使用者自行修改的名稱、順序及尺寸，避免直接覆蓋。
* 新版刪除的舊組件或無法相容的內容，移至角色卡底部「保留內容」區塊。
* 「保留內容」中的組件仍可編輯及拖曳。
* 更新前保留可還原的角色卡狀態。
* 更新失敗須完整還原，不得部分覆蓋或遺失資料。

不包含： 將既有角色卡直接更換為完全不同來源的模板。

12. 投稿下架與刪除

12.1 下架

* 作者可自行下架及重新上架。
* 保留固定連結、版本紀錄及下載統計。

12.2 永久刪除

* 須二次確認。
* 移除投稿及全部公開歷史版本。
* 刪除後不可恢復。

12.3 已下載內容

* 下架或永久刪除不得影響其他使用者已下載的私人模板或既有角色卡。
* 來源永久刪除後，已下載模板不再接收來源更新。

13. 模板改編與二次投稿

13.1 改編權限

* 作者可設定是否允許其他使用者公開投稿改編模板。
* 預設不允許。
* 不論權限如何，均允許下載、私人修改及建立角色卡。

13.2 公開改編

* 原作者允許時，其他使用者可公開發布改編模板。
* 改編作品須標註原作者及來源模板，並保留來源關係。

13.3 權限變更

* 原作者可隨時修改改編權限。
* 新設定僅影響未來投稿。
* 已合法發布的改編作品不受追溯影響。
* 保留作品發布時的授權狀態及來源紀錄。

### F-WORLD — 世界觀

- **世界觀（F-WORLD）**：結構化世界觀資料，角色可歸屬世界觀或獨立建立。

- **規格**：`creative_type: "world"`，首頁採地圖優先瀏覽；不套用性別、年齡、職業等角色編輯欄位。既有世界觀區塊／分頁與舊欄位資料保留，不因 UI 改版刪除；角色頁共用組件維持。
- **歸屬**：角色以 `character_data.world_id` 歸屬某世界觀，或為空表示獨立角色。
- **邊界**：世界觀／人物／地點與**小說**的關聯明確不做（D-201）。
- **2026-10-20 首頁改版（Refs #90）**：直接顯示選取地圖唯讀預覽；範圍（世界／地區／城鎮，可擴充）與政治／地形／氣候等顯示圖層分開。詳細圖是同世界觀內獨立地圖，可由上層開啟；無資料顯示空狀態，不假設 Azgaar 支援城鎮街道／建築。多圖新增／切換／改名／複製／刪除還原保留。預覽縮放／拖曳／全螢幕，扳手進入完整編輯，返回保留視圖與選圖，圖層／語系切換不重建核心。預覽不可寫入原專案；既有匯入匯出／草稿／離線／備份契約保留。桌機／平板／手機響應式且無水平溢出。
- **語系**：所有新增 UI 使用既有 en／zh-TW i18n；Azgaar fork UI 逐步接同語系與共用翻譯目錄（工具列、選單、圖層、設定、提示及錯誤）。未知文字回退英文，不翻譯使用者地名／國名／輸入值／地圖內容。

### F-WORLD-MAP — 世界觀地圖（Azgaar 整合，2026-10-20 已核准；Refs #88）

> 實作／驗收進度見 HANDOFF；首批資料層不等於編輯器已可使用。

#### 入口與歸屬

#### 編輯核心與功能
- **長期定位：Nexus 自有、可持續大幅改良的世界觀地圖編輯器**。以選定固定版本的 Azgaar's Fantasy Map Generator 開源程式作為開發起點，優先重用成熟功能、避免首版不必要的重寫；但 Azgaar 不是最終產品的功能或介面上限。未來允許獨立改良筆刷、圖層、地理／氣候模擬、地圖資料及世界觀整合。**不要求追蹤、同步、更新或相容 Azgaar 上游未來版本**；仍需保留授權及第三方資產聲明。
- 保留原有高度圖、地形與海岸、水系、溫度、降水、生態、文化、城鎮、國家、圖層、標籤及原有專案匯入／匯出、圖片匯出能力；不可退化成靜態圖片或唯讀嵌入。允許先只規劃地理而不產生國家。
- **分階段演進**：首版先整合可用的 Azgaar 編輯器，不為了未來想像而立即重寫地形、氣候演算法或整套 UI；後續可依 Nexus 使用需求深入改造。編輯器核心、Nexus 世界觀整合及儲存同步應有清楚的責任邊界，避免新增功能時必須重寫所有層；但不要求現在進行無必要的大型架構重構。原有氣候輸出屬地圖生成參考，不宣稱科學上精確。

#### 資料、同步與備份
- **首版以完整、可重新編輯的 Azgaar 原生地圖專案作為內容資料真相**；PNG／SVG 等是衍生輸出，不能代替專案。Nexus 地圖外層須保有自身穩定 ID、所屬世界觀、格式／版本等中繼資訊，避免 Nexus 業務資料直接耦合 Azgaar 內部資料結構；未來如需演進內容格式，應採明確版本化轉換與無損／可回復驗證，**目前不另造新地圖格式**。需可匯入、匯出完整專案並往返檢查資料無損。

- 支援離線暫存、同步重試及帳號隔離；避免反覆下載未修改地圖，保護未同步內容、衝突與多分頁使用情境。匯入未知格式或版本需顯示錯誤，不可靜默覆寫。

#### 2026-10-20 V2 地理／人文地圖設計規格（規劃基準，尚非全數實作；V2-0／V2-1 Refs #96）

> **效力與狀態**：本節整合 2026-10-20 後續討論，為後續實作的產品規格草案；已確認的使用者決策與尚需驗證的技術建議分開標示。本節在生成流程、Azgaar 原版 `.map` 互通和 UI 取捨上**優先於**本章舊版 M0–M4 要求。僅更新文件，不表示相應功能已實作。實作須分階段驗證及另行排程，不應將整份 V2 一次性重寫。

##### A. 已確認的產品決策
1. Nexus 地圖屬於既有世界觀，一世界觀可有多張地圖；長期可大幅改造 Azgaar fork，不要求追隨 Azgaar 上游。
2. **初始僅自動生成自然地理**；不自動創造隨機國家、文化、宗教、城鎮或其歷史。保留生成後的自由地理編輯；需要大改時，另設「完整重新生成」高風險流程。
3. 程序生成模板、種子碼與既有地形來源要保留；fork 在 2026-10-20 查到 `vendor/azgaar/src/data/heightmap-templates.ts` 的 14 種程序模板、`precreated-heightmaps.ts` 與 `public/heightmaps/` 的 23 種預製高度圖。**資源存在不代表所有模板已在新版 UI 通過實測**。
4. 移除語音朗讀、地球投影、3D 場景及專用設定入口；2D 地圖、地形／氣候／文化／行政檢視、標記、圖片輸出仍保留。清理依賴以實際載入及其他模組引用為準。
5. 不再以對外匯入匯出 Azgaar 原版 `.map` 互通為目標；保留 Nexus **完整可再編輯的地圖、離線保存、工作區備份還原**。禁止未完成遷移／還原驗證就改壞原有內部資料。
6. **文明內容以世界觀管理器的完整條目為正式來源**；地圖也可直接新增國家等條目，自動建立對應世界觀條目。兩入口指向同一穩定 ID；地圖負責座標、形狀與顯示，不另外複製正文。
7. 國家、行政區、文化與宗教分布可依現有條目產生**地理配置草案**並人工修正；後續新增條目可「手動配置」，大規模變動可「整體重新配置」。同步文字資料**不等於**重新配置疆界。
8. **國家／行政區面積由使用者繪製的疆界與地圖尺度自動計算**，不以使用者手動填一個面積取代。修改疆界是更正目前地圖，**不是**國家擴張、戰爭或歷史演進模擬。
9. 同一份地圖可切換及組合不同的 2D 檢視：自然地形、等高線、氣溫、降水、生態、政治／行政、文化、宗教等。檢視預設與資料及純視覺樣式必須分離。

##### B. 資料模型與權責（建議落地契約）
- **WorldEntity（世界觀條目）**：stable ID、world_id、type、名稱／別名、富文字內容、結構化關係及有效性；建議包含 geography/region、state、administrative_area、settlement、culture、religion、site／landmark 等類型。類型應可擴充；勿為每種類型複製整套富文字編輯器。
- **MapDocument（地圖）**：stable map ID、world_id、owner、地圖類型／尺度、父地圖與地理覆蓋範圍（可選）、原生自然地理內容引用、schemaVersion／revision、離線及雲端同步狀態。
- **MapPlacement（地圖配置）**：stable placement ID、map_id、entity_id（可選：純自然地理或裝飾不需對應條目）、幾何資料／格網歸屬、座標、顯示狀態、配置鎖定、來源／修訂資訊。**一條目可配置於多張地圖；同一張地圖可有多塊分離領土**。不可僅依名稱關聯。
- **MapPresentation（呈現）**：標籤位置、可見性、圖示、色彩、透明度、圖層樣式與檢視預設；不得讓改色或切換檢視改動世界觀正文及地理幾何。
- 正式來源：國家政體、歷史、文化敘述、城鎮行政隸屬、人口由 WorldEntity 管；地理疆界、實際位置由 MapPlacement／MapDocument 管；面積、人口密度、相鄰關係由可信資料計算。顯示地理與行政隸屬不一致時提示確認，不默默改寫正式隸屬。
- 新增自地圖／世界觀的雙向操作要以穩定 ID 可重試、去重與關聯恢復；地圖移除某 placement 預設**不刪除** WorldEntity；刪除正式條目需預覽關聯影響／既有 Trash 處理。
- 如現有資料承載不適合新增上述抽象，先提出最小相容過渡層；本文是**邏輯模型**，不授權直接新增 DB 表、RPC 或正式遷移。

##### V2-2A 城鎮正式條目及配置（2026-10-20；Refs #98）
- 正式城鎮資料沿用所屬世界觀 Page，透過可選條目集合管理 stable entityId/worldId/type、名稱／別名、可選摘要／Tiptap 詳細內容、關係、時間與 revision。既有 basic/sections/tabs／角色歸屬不搬移或刪除。預留國家、行政區、文化、宗教、地理區域、地標設施等可擴充分類，本批只提供城鎮 UI。
- 地圖 metadata 的可選 placements 引用 stable entityId；placementId/mapId、點座標、可見性／標籤圖示及獨立 revision，不複製正式正文。可未配置、一條目跨多圖、一圖多城鎮；改名不失聯。移動只改座標；移除標記或軟刪除地圖不刪除條目。
- 地圖人文工具：新增城鎮→點選座標→名稱／確認→同一交易建立正式條目和配置；取消不寫入。亦可選擇既有城鎮放置；點擊標記顯示資料、開啟完整條目、移動、移除（需確認）。世界觀管理器可建立／編輯城鎮，類型與摘要可選；詳細內容沿用自由編輯器，可稍後選地圖配置，不強制立即放置。
- 兩入口同一正式資料，改名即更新衍生顯示，不生成自然地理、不因文字修改重傳 native binary。交易沿用既有 owner/world/CAS／outbox，使用穩定操作 ID 保證確認後重試不重複新增；保留已刪除配置身分，舊操作不自動復活標記。錯誤／未存狀態依實際結果顯示。
- 世界觀備份保留條目及配置並驗證歸屬／引用；PNG／SVG 匯出包含衍生標記，原生 .map 僅含引擎專案，完整 Nexus 條目與配置應使用工作區備份，介面須明示此區別。世界觀複製重建 entity/map/placement IDs，地圖複製仍引用同世界觀正式條目；可重用模板不攜帶使用者實例。本批不新增資料庫或第二套世界觀系統、不做國界／文明自動配置或海陸拓撲。

##### V2-3 文化／宗教分布（2026-10-21；Refs #102；PR #103 已實作／隔離 CI 通過，待審查）
- 延用 WorldEntity、WorldRegionGeometry 及同一世界觀 Page CAS/outbox；新增文化／宗教通用表單、自由類型／正文、語言／習俗設定及 stable ID 多值關聯。同一 cell 可重疊多個文化及宗教，跨國界；國家互斥規則只適用國家。
- 同一區域筆刷提供候選、擦除、逐筆復原／重做、取消與確認；地圖新增正式條目及第一個分布同交易。移除配置不刪條目，文字不重傳 native 附件。
- 文化／宗教檢視提供個別可見性、透明度、圖例、選取高亮及點擊 cell 查詢全部分布。未選取時以等權顏色混合呈現重疊，不以繪製先後選定唯一文化；所有顯示皆為衍生圖層。預留使用者指定主要／次要與相對影響欄位，非人口統計。
- 格網不相容拒絕套用；舊 point／政治區域及原生文明不自動轉換。PNG／SVG 輸出已確認可見狀態，native .map 不含正式配置；完整資料以工作區備份保存。本批不做文明生成或傳播模擬。

##### V2-2B 國家／行政區及人工區域（2026-10-21；Refs #100）
- 沿用正式 WorldEntity，提供國家／行政區名稱、別名、自訂類型、摘要與 Tiptap 正文；relations 使用 entityId，支援 parent（行政區／城鎮→國家或行政區）、capital（國家→城鎮）、center（行政區→城鎮）、culture／religion（國家→對應類型），同世界觀／類型／單值及 parent 循環檢查。舊自由關係保留；不從原生 states/provinces 自動產生條目。
- WorldMapPlacement 保留 point，新增 cells 區域：排序唯一 cell IDs、meshId 指紋及 cellCount。共用原生 packed Voronoi 格網，支援分離領土與水域排除；不同網格不得套錯 IDs，提示不相容，不自動重投影。獨立 Polygon／爭議覆蓋模型留待後續。
- 人文工具提供新建／放置既有國家及行政區、選取資訊、加／減筆刷、連續筆畫復原／重做、即時預覽、確認提交與取消；只有明確繪製模式攔截單指，普通瀏覽／縮放沿用既有手勢。確認前不持久化候選；若關閉／切圖有候選須確認捨棄。新條目及配置以同 Page 交易建立。
- 同圖同網格國家 cell 不重疊；重分配先列出受影響國家，二次確認後同交易移轉，不改正文。行政區與上級／城鎮正式隸屬和地理不一致時顯示警告，不自動改寫關係。
- 面積從實際陸地 cell polygon 衍生，不保存另一份正式面積；飛地加總、水域不算。尺度未知顯示相對面積；世界圖不承諾球面 km²。地區／城鎮圖只有明確可信 km 尺度才顯示平面估算，標示估算及投影限制。
- 延用 CAS／outbox、穩定操作身分、配置 revision／tombstone、備份及 owner/world 檢查。疆界不重新生成地形／水文／氣候／文明，也不重傳 native 大型附件。舊地圖與 point 保持相容；原生 .map 與工作區完整備份區別沿用 V2-2A。

##### C. 比例尺、座標、面積與多尺度地圖
- **畫布像素尺寸、地理實際尺寸、投影／座標、顯示縮放**四者分離；不能由 1600×900 像素推得平方公里。地區尺度可使用局部平面座標與實際寬度等換算；世界尺度的球面投影與面積變形須額外處理。
- 第一階段保留 Azgaar 網格與既有單位，建立清楚且可儲存的地理尺度中繼資料。若缺少可信尺度，顯示相對單位／「尺度未設定」，不得提供虛假的 km² 精度。世界圖球面測地面積屬進階實作，需先驗證精度。
- 國家陸地面積排除水域（除非使用者明確選擇其他統計類別）；分離領土及飛地加總；爭議地另列統計並防止被重複算為多國正式領土；行政區可獨立計算及與上級領土檢查一致性。
- 父子地圖支援「世界 → 大陸／地區 → 城鎮」的範圍關聯與跳轉；不假設城鎮街道可由 Azgaar 直接生成。子地圖有自己的細緻內容，上層修改不得靜默覆蓋下層。條目共用 ID，幾何可有不同尺度與精細度。
- 首版**不做歷史時期模擬、戰爭／國家擴張動畫**；未來若做歷史地圖，另設時間版本資料，而非把每次畫國界當成歷史事件。

##### D. 自然地理生成與編輯流程
- 新建地圖：名稱／所屬世界觀 → 程序模板或預製高度圖 → 種子／尺寸／格網密度／必要尺度 → 低成本預覽與重抽樣 → 確認建立。進階氣候／水文參數收合。**預覽與重抽樣不得改動既存地圖**。
- 初始化只執行必要自然流水線：格網、高度、海陸、氣溫、降水、河流／湖泊、生態及必要的圖層／基礎圖形；必須實測文明資料為空時的工具／渲染／保存／匯出。原 `generation-pipeline.ts` 含文化、城鎮、國家、宗教、貿易等後續步驟，應解耦，不能只隱藏按鈕後仍偷偷生成文明。
- 完成建立後，普通編輯提供高度抬升／降低、平滑、山脈／谷地、海岸與水域、河流、氣候、生態、特殊自然區域；不提供普通隨機重抽全圖。局部地理更動可標記水文／氣候／生態「待更新」，由使用者決定重算受影響範圍。
- **手動覆蓋優先**：每次重算需識別可能覆蓋的使用者修改、標記或文明配置。不能可靠處理時顯示具體風險並拒絕無提示覆寫；不可宣稱已有單物件鎖定，除非資料層與測試真正支援。
- 完整重新生成為地圖管理中的進階高風險操作，須先製作可還原完整快照、預覽新的自然地圖、明確警示人工與人文配置後果、二次確認後才提交。取消、失敗或同步中斷不改原地圖；原有 world_id、權限與必要地圖 ID 不得錯配。重新生成**自然地圖**與重新配置**政治圖**是不同功能。
- 氣候及水文參數保持「基本／進階」分層；預設不承諾四季／月別精密模擬。奇幻特殊區域可建立獨立覆蓋圖層並連結地理條目，不強制以魔法影響底層科學計算。

##### E. 2D 檢視、圖層、等高線與樣式
- 分離 **底層資料（高度／氣溫／疆界）**、**圖層（展示哪個量）**、**檢視預設（顯示組合）**、**純樣式（配色／陰影／材質／標籤）**；任一 UI 切換不得重新產生或重存自然地理。
- 常用檢視預設：自然地形、等高線、氣溫、降水、生態、政治／行政、文化、宗教；另支援自訂。主要底圖以互斥或可控混合方式選擇，河流／湖泊、國界、城鎮、地名、道路、網格等可獨立疊加；圖例與數值單位依圖層切換。
- **等高線**必須由高度網格衍生；提供基本線距／標籤開關，進階等高距與主等高線設定。原版高度值未建立可驗證公尺換算前，不可標示為真實公尺海拔。氣溫／降水的數值意義及單位亦須忠於實際生成器。
- 切換檢視不改變編輯目標；編輯目標必須另行明示是地形、水文、國界、文化等。UI 應可恢復合理上次檢視偏好且不干擾現有地圖預覽的 fit／pinch／fullscreen 契約。
- 樣式與出圖：保留實際有用的 2D 色彩、陰影、標籤、圖例與 PNG／SVG。3D／地球投影、語音朗讀專屬入口退場；評估不用的 bundle／runtime 依賴時以測量結果為準。

##### F. 人文地理、條目編輯 UI 與配置草案
- 世界觀管理器提供**通用完整富文字條目編輯器＋依類型的少量結構化欄位**。國家：名稱、政體、首都關聯、所屬地區、文化／宗教關聯、正文；行政區：上級關係、名稱／類型；城鎮：所屬行政關係及類型；文化：起源、語言／命名、習俗與關聯；宗教：教義／神祇／信仰形式與聖地關聯。人口與經濟等非必要欄位可選，不設硬性必填。
- 地圖人文工作區以「政治與行政／文化及人口分布／宗教與信仰／聚落及設施／道路與路線」為工具群。選圖中物件可查看簡短屬性與「編輯世界觀條目」；可在地圖直接建立新條目並自動連結；或從「未配置條目」選現有項目。
- **政治疆界**：使用者筆刷／相鄰區域／邊界工具編輯；允許飛地、無主地、爭議領土的表示。正式領土與爭議／特殊覆蓋資料可採混合拓樸／覆蓋模型。建立或更改國界只更新地理配置、面積、相鄰等衍生資料，不生成戰爭或擴張歷史。
- **文化**：主要文化底圖與可重疊的次要影響區是建議的最低複雜度方案；文化與族群為不同概念，不強制一塊區域只能有一種文化；比率式人口模型非首版必需。
- **宗教**：分別表達信仰影響範圍、可選的宗教實際管轄區與獨立聖地點位；允許跨國、混合與無明確地理疆界的宗教。
- 世界觀條目變更的「**同步內容**」只更新名稱、資訊及關聯展示；地理「**手動新增**」只為選中的既存／新條目放置標記或疆界；「**整體重新配置**」只根據現有條目、地形、指定首都／相鄰條件、人工鎖定配置生成新的**待確認草案**。不自動創造新的國家、宗教或歷史。
- 配置狀態建議為「未配置／已配置／已鎖定」；整體重排要能預覽增減與衝突、保留鎖定配置，套用只更新明確被確認的地理配置。合理的自動行政疆界／文化宗教配置演算法是**後續階段、需實驗驗證**，不可在需求文件中宣稱 Azgaar 原生已支援。
- 地圖條目與世界觀條目可離線建立並待同步；重試不得重複建立。修改世界觀長文不需要整份地圖重新上傳。

##### G. UX、取捨與非目標
- Nexus 保留「地圖優先的瀏覽首頁」，詳細編輯器按 **自然地理／人文地理／顯示及樣式** 分工作區；以「選擇類別 → 對象／工具 → 地圖操作 → 側邊屬性」代替原版所有選項齊列。桌面側欄可收合，手機使用底部抽屜；地圖畫布為主，不與世界觀富文字表單爭奪版面。
- 資料相關專業參數可留在進階設定；原版人口估計、軍事、外交、商品、交易、市場、生產、稅收、旅程及動畫不作為主要地圖流程。外交／軍事等詳細敘述歸世界觀條目；未來可選擇重用原版演算法，但須確認需求，勿先刪除底層依賴。
- 圖層 UI 採常用檢視預設、可收合自訂圖層、主要底圖與疊加圖層分離、清楚圖例；地圖預覽等比 fit 與觸控縮放沿用現有地圖瀏覽 UX。
- 必要功能 i18n 先 zh-TW／en；自訂名稱、文本不自動翻譯；保留 Azgaar MIT 授權及第三方 notices。
- **非本期目標**：即時多人共同編輯、真實 GIS 全套精密氣候模擬、四季細緻計算、地圖領土征戰時間動畫、全量歷史地圖、Azgaar 完整 3D 或原版 `.map` 對外相容。

##### H. 分階段實作門檻與驗收
1. **V2-0 驗證／資料契約**：複核最新 fork 模板資源、現有 Azgaar pipeline、Nexus 世界觀／附件／同步資料結構；提出不破壞原資料的改造契約與最小 migration 評估。此階段可先只改文件與測試，不直接更新正式 DB。
2. **V2-1 自然地理與 UI**：新建模板／預覽、僅自然地理初始化、自由編輯、2D 檢視及選擇性清理語音／3D。驗收空文明地圖的建立、編輯、重開、輸出和舊地圖回歸。
3. **V2-2 世界觀共用條目**：通用條目編輯器、穩定 ID／關聯、地圖新增條目、未配置／手動配置、離線及去重。驗收同條目跨地圖引用與刪除／移除差異。
4. **V2-3 人文編輯工具**：國家／行政區疆界、城鎮、文化／宗教影響範圍、面積及衝突警示。驗收修改位置不改世界觀正文、尺度未知不顯示虛假 km²。
5. **V2-4 配置草案引擎**：根據已有條目產生可預覽政治配置，後續才加入文化／宗教。驗收鎖定、取消、部分套用和不新增隨機文明。
6. **V2-5 多尺度及可選進階**：父子地圖定位、更完整高程／球面面積及可選人口等統計；歷史版本另行評估。
- 各階段必須有 TypeScript/build/lint、相關單元／回歸及瀏覽器測試，並確認本機重開、草稿、同步／離線、帳號隔離、Nexus 工作區備份與完整還原。不得讓舊專案因新格式或新初始化流程無法開啟。
- 不因本文件核准就直接進行一次性大規模引擎重寫、付費服務導入或破壞性正式資料庫操作；需各階段可逆、可觀測、可驗收。

### F-UTILITY — 網頁與工具（計數／抽選）

- **網頁收藏（F-WEB）**：介紹資訊與連結清單編輯；公開展示另行設計。
- **計數（F-COUNTER）**：項目計數、依群組名稱彙總；階層群組設計待確認。
- **抽選（F-DRAW）**：項目庫、標籤篩選與抽選指定數量。

三者共用 `UtilityView`，資料存在 `Page.content_json`（D-218），皆為**基礎版**。

- **網頁（F-WEB）**：`intro`（介紹）＋`links[]`（`{id, label, url}`）。使用者要求「類似 lit.link」：**對外展示頁、版面設計、公開網址均未做**（依賴 M8-0／M8-1）。
- **計數（F-COUNTER）**：`counters[]`（`{id, name, value, group?}`）。「大組」以文字欄 `group` 表示，介面依名稱加總並顯示各組合計與全部合計；空的 group 顯示「未分組」。使用者原意是「一個計數項目可分大組與小組，大組是小組總和，小組可單獨存在」——**正式的大組物件與階層 UI 尚待資料模型確認**（M10-8）。
- **抽選（F-DRAW）**：`draws[]`（`{id, label, tags[]}`）；一個抽選項目 = 一個資料庫；單筆可多標籤（逗號分隔輸入）；抽取時勾選標籤，候選為**同時具備所有勾選標籤**者，再隨機抽指定數量。使用者要求的「某標籤抽幾個」「標籤配標籤」等規則**尚未做**（M10-9）。
- **新增選單**：三個功能各有對應新增項（網頁／計數項目／抽選資料庫）。
- **工具為獨立功能而非分類標籤**：導航層級以「工具」作為一個頂層功能，內含「計數」及「抽選」兩個子功能；不再於頂層功能導覽中將計數、抽選視為與工具平行的功能，也不得僅把工具實作為普通檔案分類／篩選器。點開「工具」進入正式工具首頁，再選擇內部的計數或抽選（依 PR #63 後續修正）。保留既有計數／抽選頁面、資料型別、內容、直達連結與返回來源。
- **工具的建立入口**：在工具範圍中提供「新增計數項目」「新增抽選資料庫」等對應操作；其他全域建立入口可保留直接建立的捷徑，但其導航與功能歸屬需一致。

#### 收藏、計數與抽選擴充

- 網頁收藏可整理介紹與連結清單，公開展示頁的網址、權限和版型待核准。
- 計數可依群組名稱彙總數值；大組／小組層級與調整方式待核准。
- 抽選可依標籤篩選並選取指定數量；各標籤分別抽 N 個、標籤組合與去重規則待核准。

### F-EDITOR — Editor Blocks 與內容插入

- **視覺畫布（F-CANVAS）**：以 Page／Block 引用組織視覺化內容。

| 元件 | 預期行為 |
| --- | --- |
| Paragraph、Heading、Bullet／Ordered List、Quote、Code | 基礎 Tiptap content；保存於 `content_json` |
| Link、TaskList | 真實 node／mark；編輯模式下 link 不自動跳轉 |
| Table | 8×10 picker、resize、右鍵選單、合併／拆分／平均選取範圍 |

| Inline / Block Math | Obsidian `$...$`／`$$...$$` 風格 |

| Image Insert | 在支援的編輯器中插入圖片；提供替代文字、尺寸及裁切等可設定欄位（細節待核准） |

#### 文字操作、表格與浮動選單

- 編輯器與表格提供全選、複製、貼上及剪下；一般文字輸入框使用系統文字操作選單。
- 浮動工具選單保持在視窗可見範圍；表格編輯選項由表格右鍵／情境選單開啟，可對選取儲存格執行平均欄寬等操作。
- 自訂貼上支援純文字與 HTML；圖片可透過支援的編輯器系統貼上或插入。
- Table、Presentation canvas 與觸控裝置上的編輯手勢及詳細工具尺寸待定。

#### 插入與資產管理

- 圖片可由支援的編輯器插入，提供替代文字與尺寸調整；內容附件與媒體資產庫的分類、引用及保存細節待核准。

#### 筆記通用題目工具

- 插入內容選單提供題目／自動題號、選項、答案／解析與作答空間等工具，與一般段落、表格及數學式共同使用。
- 題目與選項提供增刪、編輯、重新排序及相應的自動標號；設定項與操作細節依 `F-NOTE`。

### F-PAGEFORMAT — 筆記輸出、Document 與簡報格式

- **跨功能導覽一致性**：側欄的功能入口從首頁、筆記、字卡、字典、**網頁**、工具等任何現有功能畫面，均可正常切換。保留既有單擊切換篩選、**雙擊開啟／跳轉目標功能**的操作契約；不得因目前位於網頁功能或其他特殊視圖而攔截、失效或停留在原頁。處理切換時的未儲存內容提示、目前來源及返回導覽，不得靜默遺失資料。
- **一致的項目呈現**：新增入口與前述共用卡片預覽、「⋯」項目操作共存；新建完成後可在適當清單中找到項目，不破壞既有搜尋、篩選、排序與路由。

#### 共用介面原則

- 頁面操作保持清楚、可預期；需要輸入或確認的操作優先使用頁面內對話框。
- 桌面、平板與手機保持主要操作可觸達，側欄／彈窗依裝置寬度調整呈現。
- **各功能項目預覽**：所有有項目集合的功能頁（如筆記、文檔、字卡學習集、簡報、創作內容、網頁、計數、抽選等）都提供可用的**卡片／預覽檢視**，不局限於筆記功能。依內容類型呈現有意義且安全的摘要／縮圖、名稱及必要的更新資訊；沒有可預覽內容時提供名稱與類型等合理替代，而非空白卡片。不要求所有資料類型顯示相同的預覽細節。可保留既有列表檢視與切換方式，檢視模式不改變資料。

## 狀態與相依

第五輪 F 提供增量 SQL `supabase/migrations/20261016040000_creation_template_library.sql`，**尚未在正式 Supabase 執行**。依賴已存在的 `auth.users`、`auth.uid()`、authenticated／anon 及 `public.is_dictionary_admin()`（沿用 Nexus 專案管理員名單，不採可由使用者修改的 metadata）。無需先套用官方私人字卡來源 Migration；兩項互不依賴。

## 模型與權限

- `creation_templates`：穩定投稿 ID、作者／owner、角色卡或世界觀、官方標記、可見性、最新版本、下載數與來源授權快照。
- `creation_template_drafts`：僅 owner 可讀的結構草稿、單調遞增 revision。自動保存不修改公開版本。
- `creation_template_versions`：不可直接覆寫的發布版本；每個草稿 revision 最多發布一次。一般讀者可預覽公開來源歷史，下載 RPC 只接受當前最新版。
- `creation_template_downloads`：owner＋來源唯一的下載 receipt，固定私人 page ID。網路回覆遺失、重新整理或另一裝置重試不增加第二份副本／下載計數。新版本仍寫相同私人模板 ID，前端先明確確認；不更新既有角色卡。已刪私人模板不自動復活。
- `creation_template_reports`：具 operation ID 的檢舉；檢舉人及管理員可讀，只有管理員可處理。

五張表均啟用 RLS，只給 authenticated SELECT，無直接 INSERT／UPDATE／DELETE grants。`public.creation_template_mutate` 是 security invoker wrapper；具權限的實作放在**不得加入 Data API exposed schemas** 的 `nexus_private`，限定 authenticated 執行，固定空 search_path，逐項檢查 auth.uid、owner、admin、revision、來源授權與結構白名單。公開端不接受角色內容、個人數值、圖片、附件、examples 或未知欄位。資料與權限變更同一 SQL 交易。

作者第一次投稿確認後立即公開；新版仍須明確發布。來源改編預設禁止；首次發布重新檢查當前來源許可，保存作者／來源／許可快照。後續權限變更不追溯撤銷已合法發布的改編；新投稿重新驗證。作者可下架／重上架；管理員下架不能由作者重上架繞過。永久刪除需兩次 UI 確認及 RPC 來源 ID 確認，不修改他人的私人 pages 或角色資料。

## 已執行驗證的範圍

自動化使用隔離 PGlite PostgreSQL，載入既有真實字典 Migration／管理員函式及本次 SQL，使用 authenticated／anon／兩個 auth.uid 驗證；不是正式或遠端 Supabase staging。瀏覽器透過明示的本機測試 transport 呼叫同一真實 SQL RPC，私人副本使用真實 IndexedDB／Workspace 原子交易。Supabase Auth／PostgREST schema cache／正式 ledger／真實 JWT 與裝置尚待授權後核對。

本工作環境未提供正式 Supabase 連線與登入憑證。CLI 嘗試在唯讀 home 建立設定目錄而無法執行，未為此修改 home、正式設定或資料；未執行遠端 advisors。權限／函式 catalog 及 RLS 的隔離測試不能冒充遠端 advisors 或 staging 驗證。

## 正式套用順序（須另行授權）

1. 核對正式 ledger、相依管理員函式與角色；備份既有 pages／附件、私人模板及新資源庫表（若已存在）。確認 `nexus_private` 不在 exposed schemas，並以 Supabase advisors 核對權限。
2. 在獨立 Supabase staging 以同版本 Postgres、PostgREST／JWT 及兩個帳號套用 SQL，驗證 RLS、owner／admin、公開／私人隔離與 schema cache。既有隔離測試結果不能取代這一步。
3. 經使用者明確授權後，一次交易套用指定 SQL；不得以手動改表替代。重新整理 PostgREST schema cache（若需），確認 capability version 1 與 RPC 權限。
