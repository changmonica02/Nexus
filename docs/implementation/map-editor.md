# 地圖編輯器：現況、參考與後續順序

依據 main 的 `docs/地圖編輯器.md`；原始基準提交：5b59dcc。

## 參考程式與取捨

本輪實際閱讀下列程式，並以 Nexus 模組實作互動，不載入 planet 頁面或呼叫 Azgaar 筆刷。

- planet-simulation，提交 `d09634e7306c5859d0aafa4afe3a090b641e31bc`：[介面骨架](https://github.com/yuuranku/planet-simulation/blob/d09634e7306c5859d0aafa4afe3a090b641e31bc/site/index.html)、[圖層開關、風格及月份](https://github.com/yuuranku/planet-simulation/blob/d09634e7306c5859d0aafa4afe3a090b641e31bc/site/app/main.js)、[地圖繪製與疊加分工](https://github.com/yuuranku/planet-simulation/blob/d09634e7306c5859d0aafa4afe3a090b641e31bc/site/app/map.js)。採用側欄、底圖／疊加分離及獨立風格的互動概念，依 Nexus 文件整合成「工具／顯示」與三個顯示區塊。
- 本機 Azgaar 固定分支：`vendor/azgaar/src/controllers/heightmap-editor.ts` 的保留模式、各筆刷及高度更新；`vendor/azgaar/src/utils/brushUtils.ts` 的筆畫插值。Nexus 改用球面大圓角距離、球面筆畫取樣、自己的海平面與 Grid，不搬入平面座標或瀏覽器全域狀態。
- 保留模式平滑只取同一陸海類別的鄰格，避免海底高度滲入沿岸平滑。
- planet 的歷史時間線不直接搬入。本輪「時間」是 1～12 月氣候／水文檢視，不宣稱具有歷史模擬。

## 自有高度工具

正式實作：`src/features/worldMap/core/heightBrush.mjs`。介面 → Client → Worker → 正式 Grid → 必要海陸／Pack 索引 → 草稿與版本儲存。

- 七種筆刷：強制／漸層抬升、強制／漸層降低、平滑、擾動、直線。
- 保留模式可選陸地／海洋，分別限制在 0…100／−100…−1；自由模式可跨海平面。
- 筆刷可點選或拖曳；直線依序選起點與終點。座標表單亦可用鍵盤套用。
- 拖曳沿短大圓弧依半徑固定間距取樣，不受指標事件密度影響；整筆先在暫存高度中運算，再一次更新正式 Grid 與 Pack，不逐次重建海岸。
- 筆刷範圍游標使用相同球面角半徑；處理換日線與極區投影。
- 每筆完成後自動儲存；復原／重做以完整專案快照保存最近 12 筆操作，亦支援 Ctrl／Cmd+Z 與 Shift+Z。編輯河流或重建自然資料後清除高度歷史，避免以舊快照覆寫後來的資料。
- 指標取消不提交筆畫；忙碌、唯讀、候選替換及衝突狀態不能修改高度。
- 海洋錨點被抬升時改選仍在水下的格子；無剩餘海洋時拒絕該筆操作。
- 高度仍只有正式 Grid 一份；Pack 不成為另一份可獨立修改的正式高度。

## 自然環境重算與已知限制

高度修改後保留上次環境計算所用的地形快照，明確標示氣候、水文與生態尚未重算。手動操作才更新，重新開啟地圖不會偷偷換掉結果。河湖 ID 與基礎幾何保留。

大幅修改海岸仍可能令既有河湖與新 Pack 不相容，重算會失敗並保留原結果，不刪除河道或回滾已儲存地形。需要繼續實作河道重新對齊及具體錯誤定位。

「海岸線」目前導向自由高度工具並說明實際功能；尚未提供獨立海岸頂點編輯。河流仍為名稱、備註、座標表單及衍生資料，尚未有河道節點直接拖曳。

## Azgaar 移除要求

筆刷、筆畫取樣、游標、顯示狀態、風格與等高線由 Nexus 自行維護；筆刷獨立建置測試確認沒有其他模組依賴。

整個星球生成仍有依賴：`build-global-map.mjs` → `build-azgaar-command-tools.mjs` → `vendor/azgaar/src/generators/heightmap-generator.ts` → `.cache/azgaar-command-tools.mjs` → `azgaar-native-patch.mjs` → `natural-land.mjs`。目前不能直接刪除 vendor。

後續將模板指令執行器、模板資料與生成流程轉入 Nexus 正式核心，移除建置時擷取原始碼；另處理舊版原生地圖 iframe、資源及匯入相容策略。依法保留必要授權聲明。最終須在沒有 vendor/azgaar 與舊快取的乾淨環境完成建置、生成、編輯、匯入、儲存與重開，才算移除依賴。

## 後續順序

1. 大幅海岸修改後的河道與湖盆重新對齊，以及重算錯誤定位。
2. 獨立海岸工具、河道節點直接編輯及穩定 ID／拓撲檢查。
3. 模板執行器與生成流程內化，以固定種子與品質指標驗證新結果。
4. 政治、文化與人文疊加資料整合，不用空白開關冒充功能。
5. 球體與二十面體展開：共用正式 Grid，外部仍為圓柱投影。
6. 地底／天空的入口關聯與更完整空間操作。
7. 先決定局部高解析度資料協定，再實作幾何 LOD 與分塊渲染。

六角地圖、湖泊新工具、IUCN 第三層及特殊地形依原文件延後。

## 驗證

- `npm run test:world-map:ui`：React DOM 操作、顯示／風格實際繪製呼叫、建立階層、手機收合、月份、河湖獨立開關、座標編輯、整筆拖曳與復原／重做。使用可控 Worker；正式運算由下列整合測試驗證。
- `npm run test:world-map:height`：獨立筆刷建置、球面取樣、極區游標、換日線、筆畫原子性、Grid／Pack 同步及正式打包 Worker 儲存重開。
- `npm run test:world-map`：既有地圖與儲存回歸；另加入建立世界觀與附件同交易及失敗無殘留測試。
- `npx tsc --noEmit`；本輪新模組及直接修改的地圖模組 ESLint。
- `npm run build`：正式建置。

Chromium 在本環境仍因 `socket() failed: Operation not permitted` 無法啟動；DOM 操作測試不等於完整瀏覽器版面與觸控驗證，後者仍待可用瀏覽器環境。

本輪結果：介面／顯示 9 項、高度與 Worker 14 項、地圖回歸 54 項，共 77 項通過；正式建置、型別與上述相關模組的 ESLint 通過。介面測試另以實際 IndexedDBAdapter 驗證同交易儲存及既有工作區自動開啟。

本輪推演改良與不保留舊演算法的決策，見 [世界推演改良](world-simulation.md)。基礎網格與海岸／河流自然度比較留到下一步。
