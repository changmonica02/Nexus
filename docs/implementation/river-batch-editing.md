# 河流資料、向量與整批儲存

## 使用方式

- 「編輯資料」可重新命名、修改備註或刪除河流。刪除只移除該河流，相關支流保留並解除指向被刪河流的連結，湖泊入／出水參照同步清理。
- 「編輯向量」可連續移動同一條河流的多個既有控制點，也能切換河流繼續修改，不需要在每次移點後套用。
- 新增河流依序點選上游、轉折與河口，至少兩點；指定下游河流時，河口接至該河最近的控制點。完成新增只加入目前草稿，仍可繼續移動控制點。
- 最後按「儲存河流編輯」才進行一次 Worker 水路驗證、關係更新與正式儲存。「取消本次編輯」還原整個工作階段。
- 手機新增時收起側欄，地圖上保留完成／取消按鈕；側欄關閉時向量控制點仍可操作，重新開啟工具也不會清掉草稿。

## 實作與保護

1. 正式草稿保留整組河流，選取河流不再清除暫存幾何。移點只更新本機來源資料，不呼叫 Worker。
2. SVG 控制點以河流 ID 及點索引穩定識別。結束、取消或失去指標捕捉時清理拖曳狀態，其他控制點不因首點移動而重新掛載。儲存按鈕位於側欄／底部，不在每次移點後新增浮動的套用工具列。
3. 主河共享匯流控制點移動時，同步更新支流河口。已連接湖泊或下游河流的端點沿用鎖定規則。
4. 修改幾何的河流以橘線預覽；切換到另一條河流時，前一條的修改仍顯示。刪除的河流立即從畫布隱藏。
5. 草稿檢查點在操作暫停 350 ms 後合併寫入；儲存會等待已排程的寫入，避免完成後又出現過期草稿。
6. 草稿的 `riverEdit` 包含原始河網及幾何修改標記。恢復時先以原始河網建立繪圖，再顯示未完成向量；不會因暫時無法路由的中間編輯狀態而無法開啟草稿。
7. `editRivers` 對整批變更一次驗證，更新河湖連結並移除草稿標記；正式儲存失敗時保留編輯內容，重試不重複已成功的 Worker 推演。
8. 輸入暫時留白的名稱仍可繼續編輯；正式儲存要求非空名稱。河道循環或無法連接的控制點在最後儲存時回報，草稿保留供修正。

## 驗證

- 連續拖曳第一、第二控制點，確認第二點保持同一個 DOM 節點；未儲存前不新增 Worker 請求。
- 跨兩條河流修改後，一次儲存保留全部幾何。
- 重新命名、刪除、重新新增、取消、手機收起側欄、草稿恢復與儲存失敗重試。
- 實際正式 Worker 驗證新增、改名、整批儲存、JSON 重開、刪除及循環拒絕；既有高度交易與自然環境測試一併回歸。
- 介面驗證使用 happy-dom，並不等同真實觸控裝置驗收。
