# 生態判定、海岸接縫與連續高度編輯

## 現況與問題

1. `ecosystem-water.mjs` 以月溫、月雨、Thornthwaite PET 與 150 mm 固定土壤桶推導 T1–T6。這是潛在生態模型，不能推斷實際物種、土地利用或演替歷史。
2. `pack-ecosystems.mjs` 將整片熱帶森林、溫帶森林或草地各畫成一種顏色。即使雨林／季雨林、針葉林／落葉林的條件不同，也無從呈現。
3. 濕地要求每年 8 個月土壤水超過 120 mm、鄰近河湖、單格鄰格落差小於 50 m、年雨量大於 PET。這既把山地地格尺度忽略，也排除了由上游補水的乾燥地區洪氾平原。
4. Pack 投影多邊形已展開換日線，但生態繪製未重複 ±360° 的副本，也未套用正式陸／海遮罩。格子界線與繪製用海岸不同，於換日線及沿岸出現斷層。
5. 高度每筆都呼叫 `editHeight`，仍進入地質、氣候、河湖、生態與完整繪圖。氣候快取命中仍要重建繪圖、儲存，並顯示進度遮罩。

## 實作基準

- 正式分類保留 IUCN GET 第二層 T1–T6、TF1、F1/F2、M1/M2/M3。另以「潛在棲地」呈現氣候與地形可推斷的細分類，不宣稱為完成調查的 GET 第三層。
- 棲地判定順序：海洋／湖泊 → 嚴寒限制 → 水文濕地 → 乾燥限制 → 熱帶雨林／季雨林／山地森林 → 溫帶雨林／落葉闊葉林／常綠闊葉林／寒帶針葉林 → 灌叢、疏林、草原與莽原。不可為了多樣性強制配額或用白雜訊改變生態。
- 指標採月溫、月降水、年 PET、成長季水分比、乾季長度、最冷月、暖月數與高度。這些是可檢查的啟發式閾值，並非 IUCN 官方判定公式。
- 土壤容量由鄰格實際距離與坡度、相對地形位置估計 60–240 mm 的範圍；平坦／凹地容量較高、陡坡較低。屬缺乏土壤調查時的代理量，不偽稱真實土壤類型。
- 濕地須有低坡度、低相對地勢、河湖水源，並有持續飽和或全年河川補水的證據；河流保持線狀，不把整個地格替換成河流。
- 成長季與乾季條件區分森林和草原；乾燥且寒冷但短暫暖季的區域，不因「暖月少於兩個」便全部變成極地。
- 地圖以同一份正式海岸遮罩裁切海陸生態。海陸兩側以最近的同類生態延展覆蓋沿岸細節；只調整繪製覆蓋，不修改高程、氣候或海岸線。
- 多邊形投影使用相同 ±360° 副本；海陸填色路徑快取，平移縮放不重新推導生態。

## 高度編輯交易

1. 每筆僅以現有球面地格計算高度、更新正式高度快照與來源格預覽；不呼叫氣候、水文、地質或生態推演，也不顯示進度遮罩。
2. 保留每筆復原／重做。地圖編輯期間草稿可恢復，未儲存離開仍受保護。
3. 「儲存並退出」將整個編輯工作階段統一推演一次並儲存，成功後回到平移。失敗保留目前高度與繪製狀態，允許重試，不宣稱已儲存。
4. 切換工具、關閉地圖或外部要求儲存時，必須透過同一個完成流程，不可繞過未完成的高度交易。
5. 重新推演保留河湖身分與使用者名稱，不強制重新生成河網；重新生成河網是河流面板最底部的明確操作。

- IUCN GET 2.0： https://portals.iucn.org/library/efiles/documents/2020-037-En.pdf

## 限制

未模擬土壤母質、火災、放牧、營養鹽、珊瑚、潮汐或實際物種分布；因此不憑氣候猜測珊瑚礁、泥炭厚度或特定擾動型森林。氣候本身仍為簡化的月均平衡模型；本次不以生態閾值掩蓋氣候或地形資料的極端值。

## 本次驗證結果

- 種子 42 的實際地圖，在本機原生 Canvas 比對完整圖與分塊圖：1,036,800 像素中只有 1 像素超過 25 色階的差異門檻；換日線左右 700 組取樣中 17 組超過門檻，其餘連續。邊界附近仍容許自然色階與反鋸齒差異，並非宣稱所有邊界像素完全相同。
- 同一世界顯示 23 種潛在棲地；此數字只描述測試世界，不是強制生成配額。
- 本機 Chromium 啟動遭環境拒絕建立 ProcessSingleton socket，因此新加入的桌面／手機瀏覽器測試尚待遠端執行；不把原生 Canvas 與 happy-dom 測試當成真實瀏覽器驗收。
- 地形改變造成投影河道互相反向時，只釋放衍生循環上的水路約束，接回既有出口；不刪除河流 ID／名稱、不建立虛構的內陸排水終點。手動輸入的幾何循環仍由編輯驗證拒絕。
- 完成並取得結果的自動化測試共 52 項：36 項介面／顯示／Client／人文測試、15 項自然環境測試、1 項正式 Worker 高度與重開測試；TypeScript 與測試清單檢查通過。
- 較重的 `globalMap.test.cjs` 多次 Worker VM 流程在本機執行期間工作階段中斷，未取得完成結果；不計入通過項目，仍待 CI 驗證。

## 合併前瀏覽器回歸的效能修正

CI 的 Chromium 實測揭露，將數萬個地格放進同一填色路徑會造成嚴重的細分計算成本，高度編輯的全圖格線亦有相同問題。改為先依分類沿球面 Voronoi 外邊界合併地格，刪除內部重複邊；不平滑邊界，不改變分類數值，保留極區與整球覆蓋的反向填色。生態區域在 Worker 推導，高度來源格則以同一方法建立分色預覽；放大四倍後才畫可見格線。同解析度直接重用總覽影像，避免再逐塊重畫。

新增來源格分類、極區、換日線及整球一致分類的幾何驗證；既有像素比對結果維持一致。
