# Nexus Life 財務重構

本分支接續 `feature/life-calendar-refinement` 的 `65a1ad99a1d98f371f5a11ebeb5988ac03bdc00d`。該分支包含 PR #234 的日曆與週期任務改版，祖先包含 PR #233 的合併提交 `e76990f66c75c968402cee534bda94eefacc0a9a`。財務 PR 暫以日曆分支為比較基準。

## 稽核與入口對應

財務原有九個同級入口。現有交易、帳戶、訂閱、估值、預算、目標與投資使用同一張 `life_finance_records` 表與工作區同步。帳戶餘額原本即由期初餘額、交易及投資交易推算。舊總覽把選取月的期末餘額與期間收支並列，無日期的估值和現行匯率有可能進入歷史比較。

| 新入口 | 既有功能與操作 |
| --- | --- |
| 總覽 | 淨資產及資料日期、收入／支出／結餘、分類占比、近期交易、當月預算、下次週期交易、目標進度 |
| 收支 | 依日期分組的記帳紀錄、類型與日期／關鍵字／帳戶／分類篩選、預估支出、週期交易 |
| 資產 | 資金及負債帳戶、投資標的及買賣回報、其他資產與負債、個別估值歷史 |
| 規劃 | 整體與分類預算、財務目標、資金異動或連結帳戶餘額 |
| 分析 | 月份／年度／自訂期間、收支與結餘、分類組成、已確認週期支出、儲蓄率、月底淨資產、預算及投資績效 |
| 設定 | 齒輪入口、幣別及匯率、分類、功能顯示、隱私和日曆偏好 |

`?finance=` 沿用既有內部檢視鍵，例如 `transaction`、`subscription`、`account`、`goal`，並支援 `analysis`。原本從總覽及日曆進入財務項目的入口沿用原始資料 ID。主要新增按鈕依檢視切換。交易檢視直接開啟支出表單，收入與轉帳可在表單切換。

## 帳務與相容性

- 舊訂閱沿用原本的資料種類、ID、幣別、週期游標、付款項目和入帳來源鍵。缺少交易類型的舊資料解讀為支出；原先的訂閱期限、試用日期及取消連結可繼續編輯。
- 週期收入、支出與轉帳共用同一類型與編輯器。單次調整按預定日期保存。後續調整會在交易日切分系列。跳過期數保存於原系列。原入帳交易保留各自的交易 ID 及入帳日期。
- 確認入帳在同一個工作區交易中寫入實際交易並推進游標。同步沿用既有版本檢查、來源唯一鍵與權限隔離。轉帳的兩端由同一筆交易推算。貸款還款可填本金和利息，只有利息計入支出。
- 財務與日曆共用原始資料和日期推進。日曆直接查閱、跳過及確認財務資料。財務日期詳情沿用右側或下方排列。一般已入帳交易可從設定開啟。
- 歷史淨資產需要有日期依據。非基準幣別資產需要歷史匯率，持有中的投資需要符合日期的估值。淨資產恢復計算後仍以工作區中已登錄的資產與負債為準。目標帳戶分配與淨資產分開。
- 金額隱私按帳號及裝置保存，財務和生活總覽共用。日曆以日期、種類和狀態呈現。交易編輯中的金額欄位沿用使用者選取的顯示狀態。

## 資料庫順序

1. 先完成 PR #234 的日曆遷移，依序為 `20261128000000_life_calendar_repeat_modes.sql`、`20261128010000_life_task_executions.sql`。
2. 在隔離資料庫驗證既有工作區備份與同步，再套用 `20261128020000_life_finance_recurring.sql`。它新增週期交易及還款利息的約束、目標帳戶的部分唯一索引，並延伸既有財務關聯驗證。既有資料採原地相容，無批次轉換或資料刪除。
3. 如需回復資料庫結構，先保留已寫入的 JSON 與實際交易，備份後再由維護者移除兩項新增約束及索引，並還原 `validate_life_finance(uuid)` 的原函式定義。已入帳交易保留在原帳務資料中。

## 已知範圍

- 月、週、自訂天數、季和年沿用舊財務週期與日曆共用的日期運算。財務編輯器未整合日曆的每月第幾個星期幾、彈性達標及完成後間隔規則。結束條件支援日期或手動終止，分期餘期依日期管理。
- 確認依系列游標順序處理。已有入帳的歷史期數透過原交易管理。目標支援手動資金異動及帳戶餘額兩種進度來源，尚無逐筆交易或逐筆估值的分配介面。
- 固定支出統計依實際交易的週期來源判定。舊手動記帳若沒有週期來源，會歸入其他支出。投資績效及月底淨資產只使用工作區已有估值與匯率。
- 正式資料庫、正式部署及 PR 合併均由維護者另行處理。
