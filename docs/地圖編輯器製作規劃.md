## 1. 產品定位與正式名稱

- 兩種地圖正式命名為 **「六角地圖」**（原「地區型」）與 **「星球地圖」**（原「全球型」）。不要改用「區域詳圖／世界詳圖」等會混淆用途的名稱。
- **六角地圖**：延續現有類似《明日方舟》的**可擴張六邊形格網**構想，平面編輯與平面顯示；不是「從星球地圖放大得到的國家詳圖」，也不以某個地理範圍大小定義。
- **星球地圖**：真實球面承載全球自然地理，在地圖編輯器中提供 3D 球體與 20 面體展開編輯；外部地圖區塊**只顯示圓柱投影的平面圖**。
- 國家海岸、道路、城鎮等比全球尺度更精細的局部設計，是**另一項尚待深化的需求**；不能直接將其等同六角地圖，也不能在此時預設「世界→國家詳細子地圖」資料架構。
- 沿用世界觀地圖區塊、正式人文條目、主地表與地底／天空附屬空間及既有資料保護約束；新地圖類型不等於任意新增第二張主地表。

## 2. 星球地圖的世界座標及基礎格網

- 整顆星球是**連續真球面**，暫以地球尺度半徑約 **6,371 km** 為參考。距離、面積必須使用球面幾何，不能直接以平面投影面積冒充實際土地面積。
- 建立星球時生成**唯一固定的球面 Voronoi Grid**。Grid 的格點、拓樸及穩定 ID 在一般編輯、縮放、投影切換、氣候重算時不重生；**使用者可以修改 Grid 的高度數值**，不能直接任意改格網結構。
- 優先沿用 Azgaar 的 **Grid＋Pack** 兩層概念；Pack 是協助海岸與河流等地理運算的輔助 Voronoi 格網，不是第二套手工地形。Pack 可依海陸／相關水域拓樸改變而重建，其暫時格子 ID **不得當成長期物件身分**。必要資料與顯示須即時反映編輯結果。
- 同一份全球 Grid 同時記錄陸地及海底高度；不額外建立一張獨立海底格網。以海平面分陸海，內陸低窪不會只因高度低就自動變成湖泊。高度數值格式、物理高度換算及海平面閾值**尚待實作定義**；本輪舉例的 -100～+100 非已核准實際資料格式。
- **海岸線三層角色**：Grid 高度／水域狀態決定海陸；Pack 提供沿岸輔助格網與基本邊界；在基本邊界上產生曲折的**分形向量海岸線**供顯示。新增分形頂點**不會回寫 Pack 或 Grid**，不得假稱視覺凹凸自動增加自然計算精度。**不另建必須人工維護的獨立海岸遮罩**。程式可有衍生的海陸判定陣列或快取。
- 土地及國家面積採**球面面積**。有效面積邊界應與其宣稱的精度對應；究竟用 Pack 基本海岸或細緻向量海岸作權威邊界、如何兼顧一致性，**技術細節尚待驗證，不能先宣稱最細緻視覺線條即是精確土地面積**。
- 格網固定且不因縮放建立分級高解析度格網。

## 3. 全球生成：由初始海陸到自然環境

下列順序與各層責任已確定，演算法精度及效能仍待原型驗證：

1. **初始陸地配置**：直接隨機抽取 Azgaar 風格的組合／島嶼／群島模板、數量、大小、地理位置及方向，配置到真球面；**不先抽指定陸地比例，也不以陸地百分比作生成目標**。完成全球海陸配置後讓使用者從 3D 球體預覽並接受或重新生成。參考模板含 Shattered、Continents、Pangea、Old World；Volcano、High Island、Low Island、Peninsula；Archipelago。
2. **板塊**：在已接受的海陸及山脈分布下，推導合理的地殼、板塊、運動與邊界。參考 MapRegionizer 的概念／演算法，移植時需適應球面。單一板塊可同時含大陸地殼與海洋地殼；既有山脈不必全是目前活動邊界。**不得擅自推翻已確認的大陸輪廓與山脈**。
3. **海底地形**：依板塊推導大陸棚、陸坡、深海平原、洋中脊、海溝及海山等，寫入同一 Grid 的海底高度，不重新決定已接受的海陸輪廓。
4. **表層洋流**：採簡化球面表層模型，考慮風帶、科氏效應、陸地阻隔與海域連通，影響海表溫度與沿岸氣候；不建立完整三維海洋模擬。洋流路徑屬可編輯的基礎自然地理。
5. **逐月氣候**：建立 12 個月的簡化季節性溫度、降雨等數值，考慮緯度、地形、風、雨影及洋流；由逐月資料衍生氣候分類。不可把 Azgaar 原始降水強度直接當成真實 mm/月，實際單位換算與校準待驗證。
6. **河流／湖泊與水文**：初始依地形與自然條件生成河湖幾何，另計算流量、水量收支及可適用的季節性變化。
7. **生物群系**：依氣候、水分、地形與水域推導；以 Azgaar 原有主要生物群系為基礎，適度增加有意義的類型，細項與分類門檻待實作決定。

- 使用者可以將世界觀的奇幻設定放在**獨立覆蓋資料**，只影響顯示、敘事與附屬資料，不反過來偷偷改變自然模擬的基準數值。
- 板塊、洋流等運算內部識別不代表自動新增同名正式世界觀條目。

## 4. 地形及河湖編輯

### 4.1 高度編輯模式

僅設兩種模式：

| 模式 | 行為 |
| --- | --- |
| **保留** | 允許編輯高度，但禁止改變海陸分布；使用者可選只編輯陸地或只編輯海洋，筆刷與高度上下限依目前類別限制。 |
| **自由** | 允許把陸地改成海洋或把海底抬升成陸地；立即更新海陸狀態、必要 Pack 資料及海岸顯示。 |

- 使用者編輯的是地形高度；Grid 結構不變。一般高度修改若未改變海陸拓樸，原則上只更新 Pack 的必要數值，不必每次重建整個 Pack Voronoi。
- 「即時」指**編輯結果及必要資料即時一致**；是否在每個筆刷事件或一筆筆畫完成後重建 Pack，待實測選擇，不以全格網重建阻塞互動。
- 不採 Azgaar 的「擦除／保留／冒險」原樣三模式，不因改岸線刪除人文內容。海底城市等奇幻設定可合理存在。

### 4.2 自然物件身分與保護

- **河流與湖泊使用獨立穩定 ID**，並保存名稱、資料及必要幾何；不把 Pack 暫時格子 ID 當成唯一物件身分。
- 地形變化對既有河湖提供兩種保護方式：
  - **智慧調整（預設）**：原處有效就不改；允許程式在合理限度內小幅修正受影響的河道、湖岸、位置或水位，優先保留 ID 與內容。
  - **固定位置**：不讓程式自動搬移／改動既定幾何；保留 ID 與內容。
- **大幅變更由程式內部規範處理**，不彈出要求使用者逐項處理的警告清單。不得為保住物件而任意搬到遙遠地區。超出合理調整範圍時保留資料、不強制重配置；無效幾何不能假裝是可正常參與水文運算的有效地理。
- 這套規則適用於**使用者修改基礎地形時的河湖適應處理**，並非氣候重算會重畫河湖。
- 使用者可以透過湖泊工具修改**湖底地形、湖面水位、湖岸範圍及進出水關係**；水位、盆地與出水口必須一致，不能無條件建立穿越盆地邊緣而不合理封閉的水面。

### 4.3 自然環境重新計算

- 使用者完成地形或基礎自然地理編輯後，可手動執行**「重新計算自然環境」**。
- 重新計算更新溫度、降雨、氣候類型、生物群系、河流流量、季節性水量及湖泊水量收支等**衍生數值**。
- **不重新生成河道、湖泊幾何、水位、板塊、洋流或已確認的海陸地形**；河湖位置及幾何不能因氣候重算被擅自重寫。
- 河道及湖泊的直接手動編輯需立即反映於地圖及必要索引；與衍生氣候數值重算分開。
- 其他「重新生成特定自然基礎物件」如要提供，須另行設計，不能把它混進上述重新計算按鈕。

## 5. 星球地圖的投影及編輯介面

- **真實世界座標唯一**：所有資料落在球面，不因視圖旋轉、剪開或重排而更改地理座標、Grid ID、河湖 ID。
- **編輯器內 3D 球體**：供建立全球海陸時預覽與檢視。
- **編輯器內 20 面體展開**：星球地圖的主要平面地形編輯方式。先在檢視狀態旋轉球面／展開配置；被分開但本來相鄰的面邊以**相同顏色與配對編號**標示，使用者可以配對連接以建立較連續的編輯區域。連接只限真正相鄰的面，不允許無效重疊或不合理連接；**切開的外緣不進行跨邊筆刷編輯**。
- 20 面體只是編輯投影，容許每片有限投影變形；不更換球面 Grid，也不宣稱完全零變形。
- **外部地圖區塊的星球地圖永遠是圓柱投影平面圖**，沒有 3D 球體或 20 面體操作。
- **圓柱投影的展開經線／左右切口由地圖編輯器設定**；外部照設定顯示。此設定只改畫面投影，不改世界地理。20 面體連接布局與圓柱投影切口是不同設定。

## 6. 六角地圖、外部檢視器與共用世界觀

- **六角地圖**維持可擴張六邊形平面編輯／檢視方向；不得直接當成「星球地圖之國家細節版」。
- 外部地圖區塊對兩種地圖都維持**平面檢視**，沿用現有可重複地圖區塊、各區塊獨立檢視設定、同一專案共用資料的設計。
- **顯示方式（主要底圖）**與**可多選圖層（疊加資訊）**分離。既有地形、等高線、溫度、降雨、生態、政治、文化、宗教，以及河流、湖泊、邊界、地名、城鎮、路線等作基礎；依新自然模組擴充。
- **編輯器決定外部可選哪些顯示方式、圖層與觀看範圍**；外部使用者可於允許範圍切換，但不能修改星球投影設定。
- 外部可「單獨觀看某國家／地理範圍」的方向已提出；它是同一地圖上的範圍檢視／篩選，**不是另建一張國家地圖**。哪些範圍可選、突出顯示或隱藏其他區域、畫面操作仍**待詳細設計**。
- **人文地理與自然地理分開**：城市、國家、文化、宗教及其世界觀正文不因陸地沉沒而自動搬移或刪除；正式條目與位置配置分離，可保留未配置條目。自然地理河湖的保護規則不直接套用於人文資料。
- 已有世界觀的人文第一層「政治體／行政區／文化／宗教／路線／地標」、詳細欄位與地理配置設計繼續作為既有介面基礎，不為星球類型另造第二份正文與條目資料庫。
- 世界觀仍保留**一個主地表、多個地底／天空附屬空間**的規則。星球地圖與附屬空間的精確座標關聯方式待技術設計。

## 7. 儲存、同步及效能方向

- **完整固定 Grid＋緊湊數值陣列＋獨立地理物件＋差異同步**，作為星球地圖優先方案。
- 第一階段**不採 Minecraft 式 Chunk 分區載入**，也不因畫面縮放而增加 Grid 解析度。載入完整必要世界資料與「只繪製需要的畫面」是兩回事；必要時才依效能量測考慮分區儲存。
- 高度、逐月氣候與衍生資料可用不同緊湊陣列；可重新計算的資料是否持久儲存或快取，依重算成本決定，不能要求每次開圖都重新模擬整年氣候。
- 小範圍修改盡可能只同步實際改動的 Grid 高度或地理物件；完整基準及差異可適時整併，**不永久保存所有歷史差異**。
- 沿用 Nexus 既有 IndexedDB、owner 隔離、工作區同步／outbox、revision／CAS、備份、離線及還原安全契約；不得在本規劃中自行宣稱已有新的星球資料庫或正式 Migration。
- Pack 與可重建索引不得作為人文或河湖資料的唯一長期識別。轉換及升級需保護既有六角／舊 Azgaar 專案，不能因新類型而破壞既有地圖與正文。
- 儲存格式／數值型別／容量、同步粒度與即時 Pack 更新效能均**待實測**，本階段不提前鎖死具體數值。

## 8. 待討論或待驗證，不應誤記為既定功能

1. 六角地圖與星球地圖互相關聯、由全球範圍建立更精細地區底稿的方法（暫不設計，**不將六角地圖預設成子地圖**）。
2. 國家、行政區及其他世界觀範圍在外部單獨觀看的選單、顯示樣式與權限。
3. 球面 Voronoi、Pack 重建及海岸面積權威幾何的準確度、穩定 ID 對應與效能。
4. 球面 20 面體投影的精確公式、邊界配對／重排碰撞檢查與筆刷限制。
5. 板塊、海底地形、洋流、逐月氣候、降雨量單位校準、氣候分類及生物群系的實際演算法與測試。
6. 河湖智慧調整的位移、形狀、水位容許範圍及無效水文資料的內部處置。
7. 星球地圖與現有 Azgaar 1.154.2 fork、世界觀附屬空間、正式人文配置的實際移植／相容路徑。
8. 全球與六角地圖建立流程、工具細部畫面和實際效能驗收順序。

## 9. 與現行 SPEC／程式的界線

本文件是**後續改版規劃**，不是「已完成」宣告。現有 [SPEC](SPEC.md) 的 F-WORLD-MAP 還有以下舊階段敘述，未來批准進入實作時須依本規劃核對並**明確更新主 SPEC／ARCHITECTURE**：

- 先前對「3D／地球投影退場」的文字，與現在已確認的**星球地圖編輯器內 3D 球體**不一致。
- 先前的「預設不承諾月別氣候」與現在已確認的**12 個月簡化季節性氣候**不一致。
- 先前的「不規劃獨立區域子地圖」不應被誤解為已經否決尚待討論的**局部精細設計需求**；同時也不應反向宣稱已決定會建立子地圖。
- 既有介面使用「地區」作為**主地表／地底／天空的空間選取**，與現在正式命名「六角地圖」的地圖類型是兩回事，未來改名時不可直接把所有「地區」文字全域替換。
- 既有 Azgaar 格網重生、地圖刷新、地理模擬與同步行為不代表星球新機制已上線。若新規則與現況有差異，依功能階段安全遷移，不得直接破壞舊資料。
