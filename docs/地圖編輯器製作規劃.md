# Nexus — 地圖編輯器製作規劃

> **性質**：已確認的產品需求與技術規劃。未決定的參數、演算法細節及尚待原型驗證的部分統一列於文末。文中提及參考專案的實作不表示 Nexus 已具備該功能。

## 1. 地圖類型、空間與世界觀

| 正式名稱 | 地圖基礎 | 用途與顯示 |
| --- | --- | --- |
| **六角地圖** | 可持續擴張的六邊形格網，類似《明日方舟》式區域配置 | 自由建立區塊與世界觀地理；編輯器及外部均為平面地圖 |
| **星球地圖** | 連續的球面世界、固定球面 Grid 與輔助 Pack | 全球自然地理生成；編輯器提供 3D 球體及二十面體展開；外部僅顯示圓柱投影平面圖 |

- **六角地圖不是星球地圖的局部詳圖**。國家海岸、道路、城鎮、港口等較全球總覽精細的地圖需求，另保留為後續規劃；其與兩種地圖的關聯方式待定。
- 每個世界觀有**一個主地表**，可附加多個**地底**與**天空**空間；附屬空間可擁有各自地形及地理配置，並透過入口或地標關聯。
- 世界觀的正式人文條目、正文與地圖上的位置／範圍配置分離。地圖移除配置時保留條目，完整刪除需明確操作；多個地圖顯示區塊共享同一份世界觀及地圖來源。

## 2. 星球資料：球面 Grid、Pack 與海岸線

### 2.1 唯一球面世界

- 使用**真實連續球面**；參考半徑約 **6,371 km**。地理距離、鄰接及面積均依球面幾何處理，包含跨越經度切口與兩極的情形。
- 世界建立時生成**一套固定球面 Voronoi Grid**，在一般編輯、縮放、投影切換與衍生資料重算期間，格點、鄰接及 **Grid ID 不變**。**所有星球使用相同的固定 Grid 解析度，不提供建立時個別選擇密度**；實際統一格數待效能與精度測試決定。使用者可以修改格子的高度與相關地理資料。
- Grid 候選生成方法：**細分二十面體以取得較均勻的球面取樣點，再建立球面 Voronoi**，產生以五／六邊形為主的格子與鄰接。這是**資料格網**，不同於第 6 節供編輯的二十面體展開介面；取樣精度、統一格數與效能仍待測試。
- **陸地與海底共用同一份高度 Grid**；使用同一套地形工具抬升、降低或平滑。**高度只記錄 -100～+100 的整數刻度，不保留小數；每 1 刻度對應 100 公尺，即 -10,000～+10,000 公尺的垂直範圍，海平面固定為 0**。地形工具寫回高度時必須符合整數與上下限限制；氣候及水文計算可依刻度換算為公尺。內陸低地不會僅因高度低就自動成湖。湖底海拔、湖面高度及水域範圍是可區分的資料。

### 2.2 沿用 Azgaar 的 Grid／Pack 分工

- **Grid** 保存世界基礎取樣、固定格子身分與高度；全球地質、氣候、海洋等計算需要完整 Grid（含深海）。
- **Pack** 參考 Azgaar 的第二套 Voronoi 輔助網格：在海岸附近插入額外取樣點、排除部分不需要的深海點，提供海岸、河流及地理物件等運算所需的細節。**不是獨立海岸遮罩，也不是另一套供使用者直接修改的高度圖**。
- Azgaar 的 `pack.cells.g` 對應原始 Grid 格子；`pack.cells.h` 由 Grid 高度取得。**Pack 格子 ID 可能在重建後改變**，河湖及世界觀條目不能只靠 Pack 索引長期識別。
- 不改變海陸／相關水域配置的高度編輯，優先只同步必要數值；海陸配置改變時更新必要的 Pack 拓樸與衍生索引。**使用者應即時看到正確結果**，具體重建批次與時機依效能量測選擇。
- 星球化需改造 Azgaar 原本的**平面 Voronoi、平面鄰近查找、地圖邊界判海、距離及平面面積**邏輯；不應將左右經度接縫視為兩個不相鄰的世界邊緣。

### 2.3 海岸線與面積的分層

1. **海陸資料**：Grid 的高度與水域連通關係決定實際陸地、海洋及湖泊分類。
2. **基本海岸幾何**：從海陸交界及 Pack 頂點形成海岸輪廓。
3. **顯示用向量海岸線**：以 Azgaar 的分形細分方法，在基本線段之間插入擾動頂點，產生自然的海灣、岬角與曲折海岸。

- **分形向量頂點不自動成為 Pack 格點，也不回寫 Grid／Pack 的海陸分類**。調整分形細節僅改變外觀；不另外維護一套人工海岸遮罩。
- 土地／國家面積採**球面多邊形面積**，以實際採用的計算邊界為準；不得把細緻的視覺分形線條等同底層精確陸海範圍。Pack 基本邊界與顯示線條的面積一致性，於幾何原型時驗證。
- 原版 Azgaar 的 `pack.cells.area` 使用 **d3 平面 polygonArea**；球面星球必須替換為球面面積計算。面積指球面投影的土地面積，不是山坡斜面表面積。

## 3. 星球初始生成：Azgaar 高度模板如何組合

### 3.1 模板不是預製圖片

Azgaar 的高度模板是由**有順序的地形指令腳本**組成；每行包含操作、次數／強度及作用位置範圍，參數可帶隨機區間。Nexus 要**重用模板思想與各步驟效果**，再將局部結果映射／旋轉至球面，組成多個大陸、島嶼與群島。

| Azgaar 操作 | 在模板中的作用 |
| --- | --- |
| `Hill` | 抬升局部地形，形成高地、島體、山丘 |
| `Pit` | 降低局部地形，形成低地及破碎缺口 |
| `Range` | 沿路徑抬升，形成山脈／長形高地 |
| `Trough` | 沿路徑降低，形成谷地、裂谷狀地形 |
| `Strait` | 切出狹長水道，分隔陸塊 |
| `Smooth` | 平滑高度分布及邊緣 |
| `Mask` | 依位置施加邊緣遮罩／整形 |
| `Add`、`Multiply` | 加減或縮放指定範圍的高度 |
| `Invert` | 反轉／映射高度配置 |

### 3.2 使用哪些模板

以下名稱來自 Azgaar `heightmap-templates.ts`；**這些是腳本模板，不是 Nexus 要建立的獨立地理物件**。

| 用途 | 主要參考模板 | 核心組成／特徵 |
| --- | --- | --- |
| 大陸群 | **Continents** | 多組 `Hill` 建陸塊、`Range` 建山脈、`Strait` 切水道、`Trough`／`Pit` 分割，配合 `Multiply`／`Smooth`／`Mask` |
| 單一巨型陸塊 | **Pangea** | 周圍與中央的 `Hill`、多條 `Range`、`Trough`、平滑及高度縮放 |
| 複合舊大陸 | **Old World** | `Range` 作主脊，搭配 `Hill`、`Strait`、`Trough`、`Pit`、`Smooth` |
| 破碎群陸 | **Shattered** | 多組 `Hill`、大量 `Trough`、`Range` 及 `Pit` |
| 火山島 | **Volcano** | 高強度 `Hill`、`Range`、`Smooth`、`Mask` |
| 高島 | **High Island** | `Hill`／`Range` 抬升，`Trough`／`Pit` 雕刻，配合 `Multiply`／`Mask` |
| 低島 | **Low Island** | 多組 `Hill`、`Trough`／`Pit`，更強的高度縮放與 `Mask` |
| 半島 | **Peninsula** | `Range`、`Hill`、`Trough`、`Smooth`，搭配高度加值與 `Invert` |
| 群島 | **Archipelago** | `Range`／`Hill` 形成多個島，`Trough`／水平與垂直 `Strait` 分隔 |

- Azgaar 原始檔另有 `Atoll`、`Mediterranean`、`Isthmus`、`Taklamakan`、`Fractious` 等模板，可供後續擴充；**不把原版機率權重直接當 Nexus 的全球大陸分布規則**。
- **Nexus 的組合方式**：隨機抽取多份大陸／島嶼／群島候選模板 → 對每份選擇尺寸、緯度、經度與旋轉方向 → 轉為球面局部地形 → 安排整體大陸配置，避免不合理重疊 → 合併到同一固定 Grid 的高度資料。
- 這是**多個 Azgaar 模板結果的球面拼合方案**，不是宣稱 Azgaar 原版已內建可直接對球面逐大陸拼合的功能。
- **不先設定世界陸地比例**，也不以某個全球陸地百分比作強制生成目標。完成後在 3D 球體預覽，使用者可接受或重新生成整體配置。
- 使用者**確認大陸／山脈之後**才推導板塊；後續地質生成不得擅自改動已接受的陸地輪廓或陸上主要地形。

## 4. 板塊與海底地形：MapRegionizer 參考方案

### 4.1 推導方向

- **採用「已確認的海陸＋現有山脈 → 合理板塊與地殼 → 海底地形」**，不先用板塊生成覆蓋掉使用者接受的大陸。
- 優先參考 **MapRegionizer** 的分階段資料模型、受約束的板塊區域生長、局部板塊邊界及衍生地質特徵；它是**演算法參考**，不是直接匯入其 .NET 程式即可完成球面功能。
- 不進行完整地質年代的物理板塊運動模擬，使用程序式地質歷史與合理的地形關係。
- **一塊板塊可以同時有大陸地殼與海洋地殼**；板塊邊界不等於海岸。現有山脈有些可成為活動造山帶，有些是歷史造山痕跡，不能全部強制視為活動碰撞邊界。

### 4.2 參考哪些 MapRegionizer 模組

參考的核心順序：

`Mask / Landmasses / WaterBodies → TectonicHistory → CrustFields → PlateDomains → TectonicBoundaries → OrogenProvinces / RiftProvinces → TectonicFeatures → TectonicPlates`

| 來源模組／資料 | Nexus 採用的概念 |
| --- | --- |
| **TectonicHistory** | 從既有陸塊推估古老穩定陸核、洋盆張開、洋中脊、海溝／火山弧、裂谷、舊造山縫合線、熱點等**候選地質歷史線索**，不直接把所有線索當板塊邊界 |
| **CrustFields**（`CrustFieldMap`） | 每個位置的**大陸／海洋／大陸棚／島弧／裂谷／增生地塊**等地殼類型；另表達大陸棚、陸坡、主動／被動大陸邊緣、地殼年代及近期造山／火山歷史 |
| **PlateDomains**（`PlateDomainMap`） | 依地殼類型與地質線索配置板塊種子，採**受約束的優先權洪水填充**擴張板塊領域；考慮跨陸海代價、地殼差異及線狀地質障礙，建立主要板塊與局部微板塊，清理不合理的小碎塊 |
| **TectonicBoundaries**（`TectonicBoundaryMap`） | 以相鄰板塊的**相對運動**求匯聚、張裂、剪切，再依局部地殼判為隱沒、碰撞、洋中脊、陸裂谷、轉形斷層、背弧擴張、被動邊緣等；**同一板塊對的不同邊界段可有不同機制** |
| **OrogenProvinces / RiftProvinces** | 依有效碰撞段、活動邊界、局部地殼與歷史線索建立**造山帶影響區**與**裂谷／張裂影響區**；避免單純把一條線畫成整座山脈 |
| **TectonicFeatures** | 整理隆升、沉降、火山、地震、熱流、沉積，以及洋中脊、海溝、島弧、盆地、熱點等地質特徵，供海底地形生成使用 |
| **TectonicPlates** | 彙整板塊身分、運動、邊界與其他地質圖層供編輯與後續生成使用 |

### 4.3 Nexus 與原參考程式的差異

- MapRegionizer 預設管線可由**既有陸海遮罩**開始生成地質資訊；Nexus 將此概念改成**從已確認的球面 Grid 海陸及山脈出發**。
- MapRegionizer 的部分空間計算仍採平面／圓柱拓樸與取樣距離；Nexus 必須用**球面鄰接、球面距離、真正跨經線接縫連通**處理板塊種子、地質線段及邊界。
- **海底地形**依板塊和地殼年齡生成大陸棚、陸坡、深海平原、洋中脊、海溝及海山；結果寫回**同一份高度 Grid 的海底部分**，保護使用者確認的海陸與陸上山脈。
- 板塊、地殼、洋流均可有計算用內部 ID；**只有使用者建立的正式世界觀附屬條目**才需要額外的人文／敘事資料。
- 生成順序與保護原地形為既定需求；具體參數、球面改寫成本及地質合理性仍需原型驗證。

## 5. 洋流、逐月氣候、河湖與生態

### 5.1 全球表層洋流

- 採**簡化表層洋流（方案 B）**，使用全球風帶、科氏效應、陸地阻隔及海域連通推導大尺度流向，不做三維流體或深層海洋模擬。
- 洋流路徑屬基礎自然地理，使用者可修改；其暖／寒流效果先影響**海表溫度（SST）**，再影響沿岸溫度、蒸發與降雨。
- 海底海溝與洋中脊**不直接作為第一版表層洋流主要驅動因素**。

### 5.2 十二個月的簡化氣候

- 依緯度／季節日照、高度遞減率、海陸熱差、洋流海表溫度、季節移動風帶、水氣輸送、迎風坡抬升降雨、背風雨影等計算**12 個月的溫度及降雨**。
- 全球水氣傳播採球面連通與風向，不照搬 Azgaar 從平面地圖邊界逐列輸入的處理；沿岸與內陸氣候需能產生地中海型、季風型等季節差異。
- 由月別溫度與降水歸納**柯本氣候類型**等計算分類；類型不是使用者直接改寫的基準數值。
- 原 Azgaar 的降雨強度不是 mm／月；**須校準至有實際意義的單位與門檻**，避免以錯誤數值套用氣候分類。
- 只做逐月氣候平均，不建立逐日天氣或多年氣候動力模擬。

### 5.3 河流與湖泊

- 初始參考 Azgaar 河流生成邏輯，依坡度、集水路徑、降雨、湖泊及流域形成主河、支流、源頭、匯流與入海口。
- **河流及湖泊有獨立穩定 ID**，保存名稱、位置／幾何、關聯與詳細資料。不能因 Pack 重建而遺失身分。
- **河道／湖岸／湖面水位是可編輯基礎自然地理**；月別流量、湖泊水量收支等為衍生結果。氣候變乾可以讓河流流量降低或出現季節性斷流，但**不因此刪除河道**。
- 湖底地形、湖水表面與範圍分開；設定水位時依盆地邊緣與出水口檢查合理性，不讓水位無條件高於封閉盆地邊界。

### 5.4 生物群系

- 參考 Azgaar 既有 **13 類基礎群系**（含海洋、熱／寒沙漠、草原／莽原、熱帶季節林／雨林、溫帶落葉林／雨林、針葉林、苔原、冰川、濕地等）。
- 依**月別氣溫、降雨、水分平衡／簡化蒸散、地形及河湖**推導；適度增加有實際區別意義的群系，如**地中海灌木林、高山草甸**。分類門檻於實作時決定。
- 生物群系是衍生自然分類；魔法環境、特定奇幻生態等可放在獨立覆蓋資料，不改變自然基準計算。

## 6. 地形編輯、自然物件保護及重新計算

### 6.1 高度編輯模式

| 模式 | 規則 |
| --- | --- |
| **保留** | 使用者先選**編輯陸地／編輯海洋**；高度操作限制在對應地形與不跨越海平面的合法範圍，**海岸不變** |
| **自由** | 同一套高度工具可使**陸地沉海／海底升陸**，海陸、必要 Pack 資料及海岸顯示即時更新 |

- 固定的是 Grid **格網結構**，不是高度值。水下城市、已沉沒的國家等人文資料不因地形改變而刪除。
- 即時反映不等於每次筆刷移動均重建完整 Voronoi；可在操作週期內增量更新並保持顯示一致。

### 6.2 河流、湖泊保護

| 設定 | 程式處理 |
| --- | --- |
| **智慧調整（預設）** | 優先保留原位置及幾何；地形衝突時在合理範圍內自動調整河道、出海口、湖岸、位置或水位，**保留物件身分與文字資料** |
| **固定位置** | 不自動搬移或修改既定河湖幾何；同樣保留身分與文字資料 |

- 物件無法在合理範圍修復時，**保留原有資料，不任意搬往遠方**；無效幾何不作為有效自然水文參與計算。
- **大幅變動的限制、合法性檢查與處置由程式規則負責**，不增加逐項衝突提醒清單，也不要求使用者反覆確認。
- 上述機制專門處理**基礎地形編輯引起的河湖衝突**，不是氣候計算會自動搬動河湖。

### 6.3 「重新計算自然環境」

- 使用者編輯完成後**手動觸發**；更新**月別氣溫、降雨、海表溫度衍生值、氣候類型、河川流量、湖泊水量收支、生物群系**等計算結果。
- **不重新生成**陸海與高度、板塊、洋流路徑、河道、湖岸、湖泊位置及**湖面高度**；既有地理物件 ID 與使用者文字內容保留。
- 河流／湖泊的直接編輯與必要資料索引**即時更新**；昂貴的自然環境衍生計算才延後。
- 其他基礎自然物件若有重新生成需求，屬獨立功能，不併入此按鈕。

## 7. 星球地圖：球面視圖、二十面體編輯與圓柱投影

### 7.1 3D 球體

- **只在地圖編輯器中提供**，用於建立時預覽、旋轉及觀察世界地理；不作外部地圖檢視器。
- 地理座標與世界資料永遠固定於球面，顯示旋轉不改 Grid、Pack 或物件資料。

### 7.2 20 面體平面編輯

- 以定向的**正二十面體 20 個三角面**將球面展開為可安排的平面編輯區，接受每片有限投影誤差；不要求完全零變形。
- 使用者在**檢視狀態**選擇展開方向與面片排列，將想編輯的洲／陸地盡量集中在連續的面片上。
- **真正互相鄰接卻被剪開的兩條邊**，使用相同**顏色＋配對編號**標示；點選配對邊可重新接合、排列相連面片，並依需求解開既有連接，檢查重疊、無效循環及不合法面片關係。
- **已接合且在球面上真正相鄰的面片，視為連續編輯區域，筆刷可以跨越接合邊界**；**尚未接合的展開切口不支援跨切口筆刷編輯**。使用者可改變排列，讓目標地理落在完整可編輯區內。筆刷影響範圍以球面實際距離及固定 Grid 判定，不直接用平面投影的像素距離當作地理距離。
- 改變展開方向、連接或面片排列時，**固定球面 Grid、物件 ID 與地理座標不變**。這與底層球面 Voronoi 的取樣建構是不同層次。

### 7.3 外部的圓柱平面圖

- 星球地圖的**外部地圖區塊只呈現圓柱投影平面地圖**；六角地圖外部亦為平面。
- **圓柱投影的中央經線／展開切口由星球地圖編輯器設定**，以避免重要地理位於左右斷開處；此設定獨立於二十面體排列，不更改真實世界座標。
- 外部顯示範圍、投影和球面地理要分開處理，面積與距離依球面資料，不依畫面縮放或投影面積計算。

## 8. 外部地圖區塊、顯示方式及圖層

- 沿用世界觀中**可重複加入的地圖區塊**；多個區塊可指向同一張地圖，各自儲存觀看角度、顯示方式、圖層與資訊展開狀態，不複製地圖或正式條目。
- **顯示方式（主要底圖）**：例如地形、等高線、溫度、降雨、生態、政治、文化、宗教；可依新的板塊、洋流、氣候功能擴充。
- **圖層（可同時疊加）**：河流、湖泊、邊界、地名、城鎮、道路／路線、比例尺等。
- **編輯器決定外部可以選哪些顯示方式、圖層及觀看範圍**；外部使用者只能在開放的選項內切換，不修改星球投影切口。
- 可觀看**完整地圖**或選定**個別國家／指定地理範圍**；直接讀取已存在的正式地理範圍，不新增副本。突出選取範圍、隱藏其他範圍、縮放等細部互動另定。
- 地圖樣式、圖層與觀看範圍都是**顯示設定**，切換時不重新生成自然地理，也不更動實際編輯對象。

## 9. 自然地理、人文地理與附屬世界觀資料

- **自然基礎資料**：地形高度、河湖幾何與水位、板塊、洋流等；**自然衍生資料**：月別氣候、水文流量、氣候分類及生物群系。
- **人文資料完全獨立**：國家、行政區、城鎮、文化、宗教、路線、地標與長篇正文不會因海岸線或地形變動自動刪除或搬移。可存在海底城市、海域國家及其他奇幻配置。
- 人文條目在地圖編輯器內建立與命名；詳細資料支援**預設欄位、自訂欄位、長篇文字**。解除地圖位置／範圍配置仍保留正式條目；完整刪除另行操作。
- **山脈、森林、平原、沙漠等有名稱的自然地理**由使用者透過**附屬資料圖層**建立紀錄，包含穩定名稱／記錄 ID、地圖位置或範圍與詳細文字；不必讓所有計算結果自動變成獨立世界觀物件。
- **奇幻覆蓋圖層**只影響顯示、附屬設定與故事內容，不反過來參與自然地理基準運算。

## 10. 世界儲存、同步與效能

- 星球採**完整固定球面 Grid＋緊湊數值陣列＋獨立穩定地理物件＋差異同步**。
- Grid 高度、月別溫度／降雨等適合使用緊湊陣列；Pack、索引及衍生結果依重建成本決定保存／快取策略。**不必每次開圖重新計算全年氣候**。
- **完整世界資料**與**畫面局部繪製**分開：可載入必要的全球資料，只重畫目前畫面需要的內容。初期不採 Minecraft 式 Chunk 分區載入，也不建立隨縮放變動解析度的格網。
- 小範圍修改盡量只同步變動的格子或地理物件；保留當前完整狀態，差異適時整合，無需永久保存每次修改的歷史。
- 沿用 Nexus 既有 **IndexedDB、離線保存、owner 資料隔離、工作區 outbox、版本／CAS、備份與還原**契約。**既有 Azgaar 地圖尚未投入實際使用，舊 `.map` 核心格式的相容與轉換列為低優先級，不為其限制新版球面核心設計**；但不得因此破壞共用的世界觀條目、附件、正式資料、同步、備份與還原，也不在未驗證前逕自刪除舊資料。
- **固定 Grid ID 與河湖獨立 ID 是長期識別來源**；Pack 格子及臨時顯示頂點不可成為世界觀資料唯一索引。

## 11. 待決定／待驗證的實作細節

1. **六角地圖**與星球地圖的建立流程、可能的地理關聯；國家海岸／道路／城鎮等局部精細設計如何承載及是否繼承全球底稿。
2. 外部單獨觀看國家／指定範圍的介面、選項與顯示行為。
3. 統一固定球面 Grid 的**實際格數**、二十面體取樣、Voronoi／Pack 球面移植效能，以及海岸面積計算使用的權威邊界；**是否讓不同星球選擇解析度已定案為否**。
4. 高度刻度與換算已定案：**-100～+100 整數、每刻度 100 公尺、海平面 0**；仍待驗證地形筆刷的整數寫回、邊界值處理及相應水文精度。
5. 板塊、微板塊、造山與海底地形的球面演算法、地質參數及實際效能；MapRegionizer 參考流程的適配範圍。
6. 全球表層洋流、逐月風雨、SST、柯本分類、水量平衡與生物群系的數值模型、單位校準及驗證。
7. 河湖智慧調整的位移／形狀限制、無效幾何的內部規則，以及湖泊水位與湖盆／出口一致性。
8. 20 面體的投影公式、面片接合／重排的幾何檢查、已接合邊界的跨面筆刷與未接合切口的阻擋判定，以及實機互動。
9. 新星球格式與 Nexus 地圖附件、正式人文條目、同步及備份的相容與分期驗證；**舊 Azgaar `.map` 格式轉換僅為低優先級，不預設必須開發舊格式遷移工具**。
